## Description

ใส่ปุ๋ย 1 ครั้ง = วันที่ + ปุ๋ยที่ใส่ + จำนวนถุง ปุ๋ยเลือกจาก **ปุ๋ยที่ได้ของแล้ว** ซึ่งรวมจากหลายใบ หลายร้าน หลายวันได้ (เช่น ดีเกลือ 300฿ 100 ถุง = ร้าน ก. 60 + ร้าน ข. 40 เป็นการ์ดเดียว) โซนและเหตุผลใส่ต่อครั้ง ไม่บังคับ การแบ่งให้คนกรีดอยู่ในการ์ดปุ๋ยแต่ละใบ ไม่บังคับ (E16-S03)

## Acceptance criteria (ร่าง)

- [ ] **FZ-1** หน้าแรก (mockup v3 จอ 1, 6): การ์ดวันที่ (ค่าเริ่มต้นวันนี้ แตะเปิดปฏิทิน ย้อนหลังได้ วันอนาคตเลือกไม่ได้) · การ์ด **"เลือกปุ๋ยที่ใส่ ›"** (เลือกแล้วเปลี่ยนเป็น **"ปุ๋ยที่ใส่ ›"** พร้อมรายการสั้นต่อปุ๋ย "ดีเกลือ 300฿ · 60 ถุง · แบ่งครบ" ไม่รวมถุงต่างชนิด) · แถว "โซนที่ใส่ · เหตุผล" (FZ-6) · ปุ่มบันทึกกดไม่ได้จนกว่าจะเลือกปุ๋ย
- [ ] **FZ-2** **หน้าปุ๋ยที่ใส่ (เต็มหน้า — phone-form-ux ข้อ 12)** (จอ 2): การ์ดละ **ชนิด+ราคาต่อถุง** — รวมการ์ดเดียวเฉพาะชนิดเดียวกัน (ชื่อ/สูตร/ขนาดถุง) และราคาต่อถุงเท่ากัน ราคาไม่เท่า = คนละการ์ด (D-92) · การ์ดบอก ชื่อ · ราคา ฿/ถุง (เต็มสตางค์ถ้ามี) · น้ำหนักถุง · ร้าน (หลายร้านบอกทุกร้าน) · **"N ในสต็อก"** · การ์ดที่ยังไม่ใช้สีจาง ปุ่ม + เป็นไอคอนในกรอบสี่เหลี่ยมมุมมนซ้ายมือ (ไม่ใช่คำในวงกลม — กฎข้อ 11) แตะทั้งการ์ดได้
- [ ] **FZ-3** แตะ + → **การ์ดขยาย จำนวนตั้งต้น = ทั้งหมดในสต็อก** แก้ได้ด้วยแป้นตัวเลขในแอป (จอ 3) · ใส่ได้ไม่เกิน "ในสต็อก" — เกินแล้วช่องแดง "เกินที่มี X ถุง" กดใช้ไม่ได้ · ส่วน "แบ่งให้คนกรีด" อยู่ในการ์ด (E16-S03) · ลูกศร ⌃/⌄ ย่อ/ขยายอยู่ **บรรทัดล่างของการ์ด** เลขในสต็อกจึงไม่ขยับ (เจ้าของ 2026-11-08) · ขยายทีละการ์ด เปิดใบใหม่ใบเก่าย่อเอง · การ์ดที่ย่อแล้วบอก "ใส่ N ถุง · แบ่งครบ" / "· ยังไม่แบ่ง" (สีเหลือง) / "· แบ่งไม่ครบ" (จอ 5)
- [ ] **FZ-4** ปุ๋ยจากใบที่ยังไม่ได้ของ **ไม่อยู่ในรายการ** · ท้ายรายการมีแถว "สั่งไว้ ยังไม่ได้ของ ›" ไปหน้าใบซื้อ · สต็อกว่าง: บอกว่าปุ๋ยจะขึ้นเมื่อใบซื้อ "ได้ของแล้ว" + แถวเดียวกัน (จอ 7)
- [ ] **FZ-5** ค่าปุ๋ยของแต่ละการ์ด = ราคาสุทธิต่อถุง (หลังส่วนลดทั้งใบ) × ถุงที่ใส่ · ทุกใบในการ์ดราคาเท่ากันจึงไม่ต้องเลือกใบ; ตัดถุงจากใบที่ได้ของเก่าก่อนเพื่อนับคงเหลือต่อใบ (D-92)
- [ ] **FZ-9** **ไม่ซ้ำ ไม่เกิน** (D-93, D-94): "ในสต็อก" = ได้ของแล้ว − ใส่ไปแล้วในบันทึกอื่น (ไม่ลดตามที่เลือกในครั้งนี้) · ลิงก์ **"ใช้ทั้งหมด" ด้านบน = ใช้ทุกการ์ดเต็มจำนวน** (D-94) แก้ทีละการ์ดได้ · ปุ่มล่าง "ใช้ปุ๋ย K อย่าง" (ยังไม่เลือก = "ยังไม่ได้เลือก" กดไม่ได้) · ไม่มีแถบรวมถุงต่างชนิด · ออกด้วย ✕ ถ้าเลือกไว้แล้วถาม "ทิ้งที่เลือกไว้?" (ทิ้ง / เลือกต่อ) · กดใช้ → ปุ๋ยในบันทึก **ถูกแทนทั้งชุด** ตามการ์ดที่ใช้ จึงไม่ซ้ำ · เปิดอีกครั้งจาก "ปุ๋ยที่ใส่ ›" ตัวเลขและการแบ่งเดิมขึ้นมาให้แก้ · แก้บันทึกเก่า: ถุงของครั้งนั้นคืนกลับก่อนแล้วคิดใหม่
- [ ] **FZ-6** **แถว "โซนที่ใส่ · เหตุผล" บนหน้าแรก** (D-94 Z2) ไม่บังคับ บอก "เลือกทีหลังได้" · แตะ → หน้าเต็ม (phone-form-ux ข้อ 12): โซนเลือกได้หลายโซน · เหตุผลเป็นชิปจากรายการที่จำไว้ + เพิ่มใหม่ · ปุ่ม "เสร็จ" · **ต่อครั้ง** ไม่ใช่ต่อปุ๋ย (D-89 Q4)

## Offline / sync behavior

- ทำได้ออฟไลน์ทั้งหมด เป็น event ใหม่ใน event log (ร่างจาก solution architect: `fertilizing_recorded` / `fertilizing_changed`, targetId `fz-<id>`, ฟิลด์ `{date, lines[{lineKey, sacks, takes[{worker, sacks, auto}], rest}], pct{worker→%}, settle{worker→…}, zones[], reasons[], note}` · ❓ ส่งให้ solution architect: `lineKey` ต้องเป็น id ที่ไม่เปลี่ยน (เช่น id รายการในใบซื้อ หรือ id กลุ่ม) — ชนิด+ราคาใช้จัดกลุ่มบนจอเท่านั้น เพราะถ้าแก้ราคาใบต้นทางจากอีกเครื่อง key จะเปลี่ยนแล้วผูกกับการ์ดไม่ได้ (รีวิว 2026-11-08) · การตัดใบเก่าก่อนคิดตอน projection) — **ไม่แก้ event ค่าใช้จ่ายเดิม**
- `lines`, `pct`, `settle`, `zones`, `deleted` เป็นฟิลด์ที่ตรวจการขัดกัน (D-30): สองเครื่องแก้ครั้งเดียวกันคนละค่า → ขัดกัน ให้คนเลือก
- สองเครื่องออฟไลน์ใส่ปุ๋ยจากใบเดียวกันจนรวมเกิน: ทั้งคู่บันทึกได้ หลัง sync ขึ้นธง "ใส่เกิน" (E16-S04) ไม่ตัดทิ้งเอง
- ใบต้นทางถูกแก้ราคา/จำนวน หรือกลับเป็น "สั่งไว้" จากอีกเครื่อง: ค่าปุ๋ยคำนวณใหม่; ถุงที่ใบยังไม่ได้ของแสดง "รอของ"
