## Description

ใส่ปุ๋ย 1 ครั้ง = วันที่ + ปุ๋ยที่ใส่ + จำนวนถุง ปุ๋ยเลือกจาก **ปุ๋ยที่ได้ของแล้ว** ซึ่งรวมจากหลายใบ หลายร้าน หลายวันได้ (เช่น ดีเกลือ 100 ถุง = ร้าน ก. 60 + ร้าน ข. 40 เป็นแถวเดียว) โซนและเหตุผลใส่ต่อครั้ง ไม่บังคับ การแบ่งให้คนกรีดเป็นแถวไม่บังคับ (E16-S03)

## Acceptance criteria (ร่าง)

- [ ] **FZ-1** หน้าเดียวจบ (390×844 ไม่เลื่อน): วันที่ (ค่าเริ่มต้นวันนี้ แตะเปิดปฏิทิน) · "ใส่ปุ๋ยอะไร" · แถว "แบ่งให้คนกรีด" · แถว "ใส่โซนไหน เพราะอะไร" · ปุ่มบันทึก
- [ ] **FZ-2** "+ เพิ่มปุ๋ย" เปิดรายการปุ๋ยที่มี: **รวมเป็นแถวเดียวเฉพาะชนิดเดียวกัน (ชื่อ/สูตร/ขนาดถุง) และราคาต่อถุงเท่ากัน**; ราคาไม่เท่า = คนละแถว แบ่งแยกกัน (D-92) · แถวแสดง ชนิด · ราคาต่อถุง · คงเหลือ และบรรทัดรองว่ามาจากร้าน/ใบไหน · ใส่จำนวนด้วยแป้นตัวเลขในแอป
- [ ] **FZ-3** ใส่ได้ไม่เกินคงเหลือ (E16-S04); เกินแล้วกดบันทึกไม่ได้ พร้อมบอกว่าเหลือกี่ถุง
- [ ] **FZ-4** ปุ๋ยจากใบที่ยังไม่ได้ของ **ไม่อยู่ในรายการ** · ถ้ามีใบ "สั่งไว้" ของชนิดนั้น แสดงลิงก์รอง "มีที่สั่งไว้ N ถุง · ของมาแล้ว?" ไปหน้าใบซื้อ

- [ ] **FZ-7** บันทึกแล้วแก้ได้ทุกช่อง และลบได้ (กู้คืนได้) · ลบแล้วถุงกลับไปเป็นคงเหลือ และหนี้จากครั้งนี้หายตาม (E16-S03)

## Offline / sync behavior

- ทำได้ออฟไลน์ทั้งหมด เป็น event ใหม่ใน event log (ร่างจาก solution architect: `fertilizing_recorded` / `fertilizing_changed`, targetId `fz-<id>`, ฟิลด์ `{date, draws[{expenseId, sacks}], zones[], reasons[], note}`) — **ไม่แก้ event ค่าใช้จ่ายเดิม**
- `draws`, `zones`, `deleted` เป็นฟิลด์ที่ตรวจการขัดกัน (D-30): สองเครื่องแก้ครั้งเดียวกันคนละค่า → ขัดกัน ให้คนเลือก
- สองเครื่องออฟไลน์ใส่ปุ๋ยจากใบเดียวกันจนรวมเกิน: ทั้งคู่บันทึกได้ หลัง sync ขึ้นธง "ใส่เกิน" (E16-S04) ไม่ตัดทิ้งเอง
- ใบต้นทางถูกแก้ราคา/จำนวน หรือกลับเป็น "สั่งไว้" จากอีกเครื่อง: ค่าปุ๋ยคำนวณใหม่; ถุงที่ใบยังไม่ได้ของแสดง "รอของ"
