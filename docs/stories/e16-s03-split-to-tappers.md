## ทำไม (เจ้าของ 2026-11-06)

แบบเดิมต้องกด "เพิ่มคนกรีด" ทีละคนทุกรายการ และคนแรกได้เลขเต็มไปก่อน ต้องมานั่งแก้ ให้ขึ้นคนกรีดทุกคนมาเลย เริ่มที่ 0 คนที่ไม่รับก็ไม่ต้องกรอก

## Acceptance criteria (ร่าง)

- [ ] **SP-1** **การแบ่งอยู่ในการ์ดปุ๋ย** บนหน้าปุ๋ยที่ใส่ (E16-S02 FZ-3, D-94) ใต้ "ใส่ N ถุง" มีหัวข้อ "แบ่งให้คนกรีด · ไม่บังคับ · แบ่งทีหลังได้" · แบ่งต่อการ์ด (ชนิดเดียวกันคนละราคา = คนละการ์ด D-92) · เปิดทีหลังได้จาก "ปุ๋ยที่ใส่ ›" ของครั้งนั้น หรือจากเช็คลิสต์เตรียมขาย (E15-S01 PREP-6) — หน้าเดียวกัน การ์ดที่ยังไม่แบ่งขยายรอไว้
- [ ] **SP-2** ขึ้น **คนกรีดทุกคนที่ยังทำงาน** มาให้เลย **บรรทัดละ 2 คน** ทุกคน **เริ่มที่ 0** · ไม่มีปุ่ม "เพิ่มคนกรีด" · ตัวอักษรใหญ่ก็ยังบรรทัดละ 2 คน การ์ดยาวขึ้นและหน้าเลื่อนได้
- [ ] **SP-3** แตะช่องเลขของคน → แป้นตัวเลขในแอป (หัวข้อ "{ชื่อ} รับกี่ถุง" + "เหลือให้แบ่ง N ถุง") · ปุ่มลัด "ที่เหลือทั้งหมด N" และ "0 ไม่รับ" · กดเลขแรกแทนที่เลขเดิม · ไม่ใช้คีย์บอร์ดเครื่อง ไม่มีปุ่ม ± (กฎเจ้าของ)
- [ ] **SP-4** **เติมคนสุดท้ายให้** (D-94): เมื่อเหลือ **คนที่ยังไม่ได้แตะคนเดียว** คนนั้นได้ส่วนที่เหลือของการ์ดนั้นอัตโนมัติ มีป้าย "เติมให้" แก้ได้ (แก้แล้วป้ายหาย) · คิดแยกต่อการ์ด · ถ้าแก้คนที่เติมให้เป็น 0 → แบ่งไม่ครบ (SP-6b) · ตัวอย่าง จอ 4: แดง 25 ดำ 20 → สมชาย 15 "เติมให้"
- [ ] **SP-5** ใต้ชื่อแต่ละคนบอก "ค่าปุ๋ย ฿x" และ "เป็นหนี้ ฿y" (ตามส่วนของคนกรีด SP-7) · บรรทัดล่างของส่วนแบ่ง **อยู่ตรงกลาง**: "แบ่งให้คนกรีดรวม X ถุง" (ครบ) หรือ "แบ่งให้คนกรีดรวม X ถุง · เหลือ Y ถุง" · รวมเกินจำนวนที่ใส่ → สีเหลือง "เกิน Z ถุง" และกดใช้ไม่ได้
- [ ] **SP-6** แบ่งไม่บังคับ: ทุกคนเป็น 0 ทั้งการ์ด = "ยังไม่แบ่ง" (สีเหลืองตอนย่อการ์ด) บันทึกได้ไม่ถาม · เตรียมขายเตือน (E15-S01 PREP-6)
- [ ] **SP-6b** **แบ่งไม่ครบ** (D-92, D-93, D-94): แบ่งไปบางส่วน แล้วกด "ใช้ปุ๋ย K อย่าง" → sheet ยืนยันต่อการ์ด "{ปุ๋ย ราคา} ยังแบ่งไม่ครบ · แบ่งแล้ว X จาก N ถุง · เหลือ Y ถุง ไม่มีใครรับ" (จอ 8) มี 3 ทาง: **"คืน Y ถุงเข้าสต็อก"** (ยังไม่ได้ใส่จริง — การใส่ครั้งนี้ลดเหลือ N−Y ถุง ถุงกลับเป็นปุ๋ยคงเหลือ E16-S04) · **"สวนใส่เอง Y ถุง"** (ใส่ไปแล้ว ไม่มีใครเป็นหนี้ ค่าใช้จ่ายสวน; นับว่าแบ่งครบ เตรียมขายไม่เตือน) · ลิงก์รอง **"ยังไม่แบ่ง ไว้แบ่งทีหลัง"** (เก็บเป็นแบ่งไม่ครบ เตรียมขายเตือน)
- [ ] **SP-7** ส่วนของคนกรีดตั้งต้น 50% (FERT-4, จากหมวด) · **แตะบรรทัด "เป็นหนี้" ของคนนั้น** → sheet แก้ % รายคน (D-94 ข้อ 10) · วิธีคืน: หักตอนขายยาง (ค่าเริ่มต้น) หรือจ่ายสดแล้ว
- [ ] **SP-8** **หนี้เกิดเมื่อบันทึกการแบ่ง** · **การใส่ปุ๋ย 1 ครั้ง = หนี้ 1 ก้อนต่อคน** (รวมทุกชนิดปุ๋ยในครั้งนั้น ไม่แยกตามใบซื้อ) · ในประวัติหนี้แสดง "ใส่ปุ๋ย {วันที่} · ดีเกลือ 40 ถุง · 15-15-15 5 ถุง" ยอด = Σ ค่าถุงที่ได้ × ส่วนของคนกรีด (D-89)
- [ ] **SP-9** ก้อนหนี้เป็นรายการในประวัติ — ยอดค้างรวมและแผนผ่อนยังเป็นชุดเดียวต่อคน (D-59, D-89 Q10; ผ่อนกี่งวด D-88 อยู่ใน PR #154 ยังไม่ merge) · **ประวัติหนี้บอกว่าก้อนไหนหักหมดแล้ว** (D-92): ป้ายเขียว "หักหมดแล้ว" มีคำ · ก้อนที่หักไปบางส่วนบอก "เหลือ ฿ X"
- [ ] **SP-10** แก้การแบ่ง/ราคาต้นทาง/ลบการใส่ปุ๋ยทีหลัง → ก้อนหนี้คำนวณใหม่ และมีบรรทัดในประวัติหนี้บอกว่าเปลี่ยน · ถ้าหักไปแล้วเกินยอดใหม่ ใช้กติกาหักเกิน (D-61)
- [ ] **SP-11** แถวคนกรีดไม่มีปุ่มวงกลมคำสั้น (กฎเจ้าของ 2026-11-06 ข้อ 11); ไม่มีข้อความกันลืม — ใช้ปุ่มที่กดไม่ได้แทน

## Offline / sync behavior

- การแบ่งเก็บใน event ของการใส่ปุ๋ย (`lines[].takes[{worker, sacks, auto}]`, `lines[].rest: null | 'farm' | 'later'`, `pct{worker→%}`, `settle`) — คืนเข้าสต็อกลด `lines[].sacks` ไม่เก็บเป็น rest เป็นฟิลด์ที่ตรวจการขัดกัน (เงิน/จำนวน D-30)
- หนี้เป็น projection id `<fzId>:<workerId>` (ก้อนเดียวต่อคนต่อครั้ง) — ไม่เขียน `debt_added`
- ใบต้นทางยังไม่ได้ของ (เพราะ sync จากอีกเครื่อง) → ก้อนหนี้แสดง "รอของ" ไม่นับในยอดค้างจนได้ของ
