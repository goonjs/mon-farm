# Story E03-S01: บุคคลและผู้ซื้อ เป็นข้อมูลหลักที่ sync

Status: Draft

## Context

- Epic: `docs/epics/e03-master-data.md`
- PRD: MD-5, MD-6, SYNC-4, SYNC-10 · Decision log "ถูกแทนที่โดยไม่ต้องถาม" (ที่เก็บรายชื่อคนในเครื่อง → ข้อมูลหลักที่ sync)
- แทนที่: S16 — `src/store/people*.ts` (ที่เก็บในเครื่อง) → ข้อมูลหลักของกลุ่มฟาร์ม; `PeoplePicker` ใช้ต่อ เปลี่ยนแหล่งข้อมูล; คงกฎ stable id + เก็บถาวรแทนลบ
- ขึ้นกับ: E01-S02 (event id ทั่วโลก), E01-S09 (outbox sync), E01-S04 (Soft Delete), E02-S02 (กลุ่มฟาร์ม)

## คำอธิบาย

ย้ายรายชื่อคนจากเครื่อง (S16) ไปเป็นข้อมูลหลักของกลุ่มฟาร์ม ที่ทุกเครื่องเห็นเหมือนกัน
เพิ่มบทบาทของคนและรายชื่อผู้ซื้อ เป็นรูปแบบแรกของ "ข้อมูลหลักเป็น event" ที่ story E03 อื่นใช้ต่อ

## Acceptance criteria

- [ ] สร้าง / แก้ชื่อ / เก็บถาวร บุคคลได้ ทุกครั้งเป็น event ของกลุ่มฟาร์ม; แก้ชื่อแล้ว id ไม่เปลี่ยน (MD-5)
- [ ] บุคคลมีบทบาทได้มากกว่าหนึ่ง: คนกรีด · ผู้จัดการสวน · ผู้จ่าย · ผู้เช่า; ไม่จำเป็นต้องมีบัญชี login (MD-5)
- [ ] คนที่เก็บถาวรไม่ขึ้นในตัวเลือก แต่บันทึกเก่าที่อ้างถึงยังแสดงชื่อได้
- [ ] ผู้ซื้อ: เพิ่ม / แก้ / เก็บถาวรได้; การขายใหม่ใช้ผู้ซื้อรายล่าสุดเป็นค่าเริ่มต้น (MD-6)
- [ ] `PeoplePicker` อ่านจากข้อมูลหลักชุดนี้ และกรองตามบทบาทได้
- [ ] เครื่องที่ 2 ในกลุ่มเดียวกันเห็นคนที่เครื่องแรกสร้าง หลัง sync (SYNC-4)

## Offline / sync

- สร้าง/แก้ได้ออฟไลน์ ใช้ได้ทันที สถานะ Pending Sync; sync อัตโนมัติเมื่อมีเน็ต (SYNC-1/2)
- แก้คนเดียวกันซ้อนจากสองเครื่อง → ใช้กลไก Conflict ของ E01 ไม่ทับเงียบ ๆ
- ข้อมูลหลักแยกตามกลุ่มฟาร์ม (rules ฝั่งเซิร์ฟเวอร์, NFR-5)

## Test plan

- [ ] Vitest (core): projection ของ event บุคคล/ผู้ซื้อ — สร้าง แก้ชื่อ เก็บถาวร บทบาท ผู้ซื้อล่าสุด
- [ ] jest-expo: `PeoplePicker` กรองตามบทบาท, สร้างแล้วเลือกในขั้นเดียว (คงจาก S16)
- [ ] Playwright: สร้างคนตอนออฟไลน์ → reload → ยังอยู่ + สถานะ Pending Sync
