# Story: E11-S13 แก้ชื่อรายการในใบซื้อที่บันทึกแล้ว

Status: Review (Q1–Q4 ตอบแล้ว 2026-11-04)

## Context

- Epic: `docs/epics/` E11 (ค่าใช้จ่าย) — ต่อจาก `docs/stories/e11-s11-fertilizer-order.md`
- เจ้าของรายงาน 2026-11-04 (ภาพหน้าจอ): แผ่น "แก้รายการ" ของ "ดีเกลือ" 38 กระสอบ — "แก้ชื่อรายการไม่ได้"

## สาเหตุ (ตรวจในโค้ดแล้ว)

- ชื่อรายการ = `Expense.item`. ปุ๋ย: สร้างจาก `fertilizer.formula` + `brand` (`productName`) ตอนเลือกจาก "ซื้อปุ๋ยอะไร" หรือ "ปุ๋ยใหม่". ของอื่น: พิมพ์เอง (`OtherItemSheet`)
- ตอน **จดใบ** (ยังไม่บันทึก) แก้ได้แล้ว: ปุ๋ยมีปุ่ม "เปลี่ยน" กลับไปเลือกปุ๋ย, ของอื่นมีช่องชื่อ
- ตอน **ดูใบที่บันทึกแล้ว** (`order-detail/edit-item-sheet.tsx`) แผ่น "แก้รายการ" แก้ได้แค่จำนวน ราคา ส่วนลด — ชื่อเป็นข้อความเฉย ๆ, `editItemPatch` ไม่ส่ง `item`/`fertilizer.formula` → **นี่คือจุดที่เจ้าของเจอ**
- หนี้คนกรีดที่ผูกกับรายการ (`shareDebts`) อ่านชื่อจากรายการล่าสุดทุกครั้ง → แก้ชื่อแล้วชื่อในหนี้ตามเอง ไม่ต้องเขียน event หนี้เพิ่ม; ยอดเงินไม่เปลี่ยน

## Offline / sync behavior

เขียนลง event log บนเครื่องก่อนเสมอ (`expense_changed` ต่อท้าย, baseEventId = head ปัจจุบัน) ใช้ได้โดยไม่มีเน็ต; sync อัตโนมัติเมื่อมีเน็ต; ชนกัน = conflict ตามเดิม (ไม่ merge เงียบ) เพราะ patch เดียวรวมชื่อและเงิน. การแก้รายการปุ๋ยที่จำไว้เป็น `fert_option_set` อีกตัว (target ต่างกัน, base = head ของ option) จึงไม่ atomic กับรายการ: เขียนหลังรายการสำเร็จ ถ้าล้มเหลวแผ่นค้าง กดซ้ำ = เขียนรายการซ้ำด้วยค่าเดิม (ไม่เปลี่ยนยอด) แล้วเขียน option อีกครั้ง

Offline/sync checklist: ใช้ได้ไม่มีเน็ต ✔ (e2e ออฟไลน์), เขียนลง log ทันที ✔, sync ใช้กลไกเดิม (ไม่ได้ทดสอบกับ Firestore emulator ในงานนี้), conflict ใช้กลไกเดิม ✔, ล้มเหลวกลางทาง = สถานะสอดคล้องและลองใหม่ได้ ✔ (เทสต์), สถานะ sync ใช้ป้ายเดิมบนหัว, ไม่พบกรณีข้อมูลหาย
