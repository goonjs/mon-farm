## คำอธิบาย

สมาชิกสร้างรหัสเชิญ 6 หลัก แล้วส่งให้อีกคนเอง (เช่น ทาง LINE) ผู้ถูกเชิญ login แล้วพิมพ์รหัสในแอป
กลายเป็นเจ้าของสิทธิ์เท่ากัน และเห็นข้อมูลกลุ่มชุดเดียวกันหลัง sync

## Acceptance criteria

- [ ] สมาชิกสร้างรหัสเชิญ 6 หลักได้ แสดงรหัส + วันหมดอายุ พร้อมคัดลอก/แชร์ (เช่น ทาง LINE) (ACC-2, D-25)
- [ ] รหัสหมดอายุใน 7 วัน และใช้ได้ครั้งเดียว (D-25)
- [ ] ผู้ถูกเชิญ login แล้วพิมพ์รหัส → เป็นสมาชิก `role: 'owner'` (ACC-4)
- [ ] รหัสผิด / หมดอายุ / ใช้แล้ว → ข้อความไทยบอกเหตุ และเข้ากลุ่มไม่ได้
- [ ] ไม่จำกัดจำนวนเจ้าของในกลุ่ม (คาดว่า 3 คน แต่ไม่บังคับ) (ACC-4)
- [ ] หลังตอบรับและ sync ผู้ถูกเชิญเห็นข้อมูลกลุ่มเดียวกับเจ้าของคนอื่น (SYNC-4)
- [ ] คนที่ไม่ได้รับเชิญเข้ากลุ่มเองไม่ได้ — บังคับที่ rules (ACC-5, NFR-5)
- [ ] ข้อความเชิญ/ตอบรับเป็นภาษาไทย

## Offline / sync behavior

- การตอบรับต้องมีเน็ต (เซิร์ฟเวอร์ต้องยืนยันคำเชิญ) — ขึ้นข้อความไทยชัดเจนเมื่อออฟไลน์
- หลังตอบรับ ข้อมูลกลุ่มดึงลงมาเก็บในเครื่องแล้วใช้ออฟไลน์ได้ (ACC-6)

## Test plan

- [ ] jest-expo: หน้าจอเชิญ + ตอบรับ, สถานะออฟไลน์
- [ ] integration: 2 ผู้ใช้บน emulator — เชิญ → ตอบรับ → เห็นการขายเดียวกัน

## ต้องให้เจ้าของทำ/อนุมัติ

- ถ้าการตรวจรหัสต้องใช้โค้ดฝั่งเซิร์ฟเวอร์ (Cloud Functions) → อนุมัติค่าใช้จ่ายและ deploy

## หมายเหตุเทคนิค (ให้ผู้ implement ตรวจ ยังไม่ตัดสิน)

- ตรวจว่ารหัส 6 หลัก (หมดอายุ 7 วัน, ใช้ครั้งเดียว) ตรวจด้วย Firestore rules อย่างเดียวได้ไหม หรือต้องใช้ Cloud Function
  — รายงานผลก่อนเลือก ถ้าต้องใช้ Cloud Function ต้องขออนุมัติตามข้อด้านบน

## คำถามเจ้าของ

- วิธีเชิญ: ลิงก์ / รหัส / ระบุอีเมล Google
- คำเชิญหมดอายุไหม ใช้ได้กี่ครั้ง
- จำกัดจำนวนเจ้าของในกลุ่มไหม

**คำตอบเจ้าของ (2026-10-03):**
- รหัส 6 หลัก — เลือกเพราะสร้างถูกกว่าลิงก์: ไม่ต้องทำ Android deep link / assetlinks; ทั้งสองแบบตรวจด้วย rules เหมือนกัน
- เจ้าของส่งรหัสให้เอง (เช่น ทาง LINE) ผู้ถูกเชิญพิมพ์รหัสในแอป
- รหัสหมดอายุใน 7 วัน ใช้ได้ครั้งเดียว
- ไม่จำกัดจำนวนเจ้าของ (3 คนคือขนาดที่คาดไว้ ไม่บังคับ)
