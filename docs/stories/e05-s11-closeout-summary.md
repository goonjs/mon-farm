## ทำไม

รันแอปจริง 390×844 ขายปกติ 2 คนมีหนี้ทั้งคู่: 5 จอ + 3 sheet · ~15 แตะ · สรุปยอดส่วนแบ่งยาว 2.3–2.6 จอ · sheet หักหนี้สูง 1.6 จอ ปุ่มบันทึกอยู่ล่างสุด · ช่องยอดหักใช้แป้นพิมพ์เครื่อง + ปุ่ม − + · ตัวเลขเดิมโผล่ซ้ำ 4–5 ครั้ง · เทียบยอดเป็นอีกหน้าต้องกดผ่าน · ช่องติ๊กของคนที่ได้เงินสด 0 (รายละเอียด: proposal §1)

## Description

ลดเหลือ 3 ขั้น: ตรวจยอดกับคนซื้อ (ไม่เปลี่ยน) → **สรุปจ่ายเงิน** (หน้าเดียว) → จ่ายเงิน/ปิดการขาย. หน้าสรุปจ่ายเงินแสดงการ์ดต่อคนกรีด โดย "เงินสดที่ต้องจ่าย" เป็นตัวเลขใหญ่สุด ตามด้วย ส่วนแบ่ง และแถวหักหนี้ที่แอปเสนอไว้ให้ · ปัดเศษและวิธีรับเงินคืนหนี้อยู่ในการ์ด "จัดเงินสดกับคนรับซื้อยาง" (CO-19), หักกลบเป็นลิงก์รองในแผ่นแก้ยอด (CO-7) · บัญชีรับโอน (D-80) ไม่มีจอใน mockup นี้ ใช้ของเดิม E05-S07 · เทียบยอดเหลือเป็นแถบ "ตรงถึงสตางค์"

## กติกาเดิมที่ story นี้เปลี่ยน (เจ้าของยอมแล้ว · แก้ PRD แล้ว 2026-10-31)

- เจ้าของยอมครบ (Q1–Q12) และแก้ PRD แล้ว 2026-10-31: **D-60** ยอดหักเสนอ + ยืนยันครั้งเดียว (Q1, Q8) · **D-72** ยุบหน้าเทียบยอดเป็นแถบ (Q4) · **D-85** หนี้อยู่ในการ์ดคน หลัก "หนี้ไม่ใช่ยอดขาย" และตรวจ 3 ข้อคงอยู่ใน "ดูที่มา" (A8) · **D-71** ใช้ทางรับเงินคืนครั้งก่อน · **D-67** ค่าครั้งก่อนเก็บในเครื่อง ไม่ซิงก์ (Q10, Q12) · **epic E05** ปัดเศษใช้ค่าครั้งก่อน ครั้งแรก "ให้คนกรีด" (Q3) · ค้าง: แจ้ง architect เรื่องค่าเก็บในเครื่อง (D-67/D-71) ก่อนสร้าง

## ไม่เปลี่ยน (ต้องมี test พิสูจน์)

- ลำดับคำนวณ ส่วนแบ่ง → หักหนี้ → ปัดเศษ → เงินสดที่ต้องจ่าย (D-60); หักไม่เกินส่วนแบ่ง (+หักกลบ) เงินสดไม่ติดลบ (D-18)
- Σ ทุกก้อน = ยอดขายถึงสตางค์ (D-72, NFR-3); ทั้ง 3 ทางรับเงินคืนหนี้ (D-71) ผลเท่าเดิม; หักเฉพาะหนี้ที่ติดสวน (D-69); หักกลบเจ้าของกดเอง (D-60)
- ธง "หักเกินส่วนแบ่ง" และ Conflict ยังห้ามปิดการขาย/ติ๊กจ่าย (D-61, D-29); event เดิมทั้งหมด ไม่มีชนิดใหม่ ซิงก์ได้ออฟไลน์เหมือนเดิม
