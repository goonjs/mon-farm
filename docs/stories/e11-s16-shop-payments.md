# Story E11-S16: จ่ายเงินร้าน — มัดจำ จ่ายบางส่วน จ่ายเต็ม แยกจากการรับของ

Status: Draft (D-90, 2026-11-06 — AC ร่าง)

## Context

- Epic: `docs/epics/e11-finance.md`
- PRD: FIN-2, FERT-1 · D-62, D-90 · ปิดคำถาม E11-S11 Q2 (จ่ายร้านทีหลัง) และ Q4 (ติดร้าน/จ่ายเป็นงวด — เฉพาะจ่ายหลายครั้ง)
- แตะ: หน้าสั่งซื้อ (`src/v2/money/order/`), หน้าใบซื้อ (`order-detail`), ปุ่ม "ของมาแล้ว"

## Description

ใบซื้อมีสองเรื่องแยกกัน: **ส่งของ** (สั่งไว้ → ได้ของแล้ว — มีอยู่แล้ว) กับ **จ่ายเงินร้าน** (ใหม่) ตอนสั่งใส่ได้ว่าจ่ายไปเท่าไร เต็มหรือมัดจำบางส่วน ตอนรับของจ่ายเพิ่มได้ ไม่จ่าย / จ่ายส่วนที่เหลือ / จ่ายเต็ม

## Acceptance criteria (ร่าง — PAY-1/2/3 จากคำตอบเจ้าของ; PAY-4…7 เป็นค่าแนะนำ รอเจ้าของ)

- [ ] **PAY-1** หน้าสั่งซื้อมีแถว "จ่ายร้าน" ค่าเริ่มต้น **"ยังไม่จ่าย"** (D-90) · แตะ → sheet: ยังไม่จ่าย / จ่ายเต็ม {ยอดทั้งใบ} / จ่ายบางส่วน (ใส่ยอดด้วยแป้นตัวเลขในแอป) · ใครจ่าย (ใช้ "ใครจ่ายไปก่อน" เดิม: เงินสวน หรือคน → เงินที่ต้องคืน FIN-3)
- [ ] **PAY-2** หัวใบซื้อแสดง "จ่ายแล้ว ฿ X · ค้างร้าน ฿ Y" (ย่อตามกฎบรรทัดสรุป) · จ่ายครบ = ป้ายเขียว "จ่ายครบ"
- [ ] **PAY-3** กด "ของมาแล้ว": sheet เดียวถามจ่ายร้านพร้อมกัน — ไม่จ่าย / จ่ายส่วนที่เหลือ {Y} / จ่ายเต็ม (ถ้ายังไม่เคยจ่าย ส่วนที่เหลือ = เต็ม จึงเหลือตัวเลือกเดียว) / ยอดอื่น · ค่าเริ่มต้น "ไม่จ่าย" ไม่เดาว่าเงินออก · จ่ายครบแล้วไม่ถาม
- [ ] **PAY-4** (แนะนำ) จ่ายเพิ่มทีหลังได้ทุกเมื่อจากหัวใบ ("บันทึกจ่ายร้าน") แต่ละครั้งมีวันที่ ยอด ใครจ่าย · แก้/ลบรายการจ่ายได้
- [ ] **PAY-5** (แนะนำ) จ่ายเกินยอดใบไม่ได้ (กดบันทึกไม่ได้ พร้อมบอกยอดค้าง) · ใบที่แก้ราคาลงจนจ่ายเกิน → ธง "จ่ายเกิน ฿ Z" ให้แก้
- [ ] **PAY-6** (แนะนำ) ยอดค่าใช้จ่ายสวนยังนับตอนได้ของ (ไม่เปลี่ยน FIN-2 ในสตอรี่นี้) · รายงานกระแสเงินสด (E11-S08) ใช้วันที่จ่ายจริงภายหลัง
- [ ] **PAY-7** ❓ (แนะนำ) ข้อมูลเดิม: ใบที่ได้ของแล้วและมีคนจ่าย = จ่ายครบ ณ วันที่ใบ · ใบที่ "ยังไม่บันทึกคนจ่าย" = ยังไม่จ่าย · ไม่แก้ event เดิม (อ่านแบบนี้ใน projection)
- [ ] **PAY-8** แถว/การ์ดไม่มีปุ่มวงกลมคำสั้น ใช้ทั้งแถวเป็นที่แตะ (กฎเจ้าของข้อ 11)

## Offline / sync behavior

- การจ่ายแต่ละครั้งเป็น event ใหม่ผูกกับ `orderId` (ไม่ใช่ฟิลด์ทับกัน) จึงรวมจากสองเครื่องได้โดยไม่ขัดกัน · แก้ยอดรายการจ่ายเดิมจากสองเครื่อง = ขัดกัน (เงิน, D-30)
- ทำได้ออฟไลน์ทั้งหมด

## Test plan

- [ ] core: มัดจำ + ส่วนที่เหลือ = ครบ; จ่ายเกินถูกกัน; ข้อมูลเดิมอ่านถูก; สองเครื่องจ่ายคนละครั้ง
- [ ] UI: ค่าเริ่มต้นยังไม่จ่าย, sheet ตอนของมา, หัวใบจ่ายแล้ว/ค้าง
- [ ] e2e ออฟไลน์: สั่ง + มัดจำ → ของมา + จ่ายที่เหลือ → จ่ายครบ

## ประเด็นค้าง (ค่าแนะนำ — ยังไม่ได้ถามเจ้าของ)

- ❓ ใบเดิมที่ได้ของแล้วและมีคนจ่าย ถือว่าจ่ายร้านครบไหม (PAY-7) — แนะนำ: ใช่ ไม่อย่างนั้นทุกใบเก่าจะขึ้น "ค้างร้าน"
- ค่าใช้จ่ายสวนควรนับตอนจ่ายแทนตอนได้ของไหม → คงนับตอนได้ของ (แนะนำ, ไม่ถามจนกว่าจะทำรายงานกระแสเงินสด)
