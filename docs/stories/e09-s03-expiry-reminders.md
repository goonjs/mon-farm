# Story E09-S03: เตือนเอกสารใกล้หมดอายุ

Status: Draft

## Context

- PRD: DOC-3, DOC-4, TASK-3, TASK-4, TASK-5, TASK-7
- ขึ้นกับ: E09-S02, E08-S02 (งานที่ระบบแนะนำ), E08-S05 (ตัวส่งตามเวลาฝั่ง server + push)

## คำอธิบาย

คำนวณสถานะ "ใกล้หมดอายุ" จากวันหมดอายุ แล้วเตือนเจ้าของก่อนล่วงหน้า
90 / 60 / 30 / 7 วัน (แก้ได้) เตือนซ้ำจนกว่าจะจัดการ และเสนองานต่ออายุ

## Acceptance criteria

- [ ] ระยะเตือนค่าเริ่มต้น 90/60/30/7 วัน แก้ได้ทั้งระดับกลุ่มและรายเอกสาร (DOC-3)
- [ ] เอกสารเปลี่ยนสถานะ ใช้งานอยู่ → ใกล้หมดอายุ → หมดอายุ ตามวันที่ (DOC-4)
- [ ] การเตือนเอกสารเปิดเสมอ (ไม่ต้อง opt-in) ส่งถึงเจ้าของเป็นค่าเริ่มต้น; เพิ่มอาจารย์สมหวังได้รายเอกสาร ไม่เพิ่มอัตโนมัติ (TASK-4, TASK-5)
- [ ] เตือนซ้ำจนกว่าจะจัดการ และไม่ส่งการเตือนซ้ำซ้อนในรอบเดียวกัน (DOC-3, TASK-7)
- [ ] การเตือนมีตัวเลือก สร้างงาน · ไม่จำเป็น · ดูข้อมูลเพิ่ม; ไม่สร้างงานเองโดยไม่ยืนยัน (DOC-4, TASK-3)

## Offline / sync

- สถานะใกล้หมดอายุคำนวณในเครื่องจากวันหมดอายุ → แสดงในแอปได้แม้ออฟไลน์
- push มาจาก server ตามเวลา (E08) — ถ้าเครื่องออฟไลน์ push อาจมาช้า แต่รายการยังขึ้นในหน้าวันนี้ (E13-S01)

## Test plan

- [ ] Unit: ฟังก์ชันสถานะ/รอบเตือนจากวันที่ (ขอบ 90/60/30/7, วันนี้ = วันหมดอายุ, หมดแล้ว) โดยใช้นาฬิกาจำลอง
- [ ] Unit: ตัดรายการเตือนซ้ำ (dedupe) ข้ามเครื่อง
- [ ] Integration: ตัวส่งฝั่ง server ส่ง push ครั้งเดียวต่อรอบ ใน emulator

## คำถามเจ้าของ

- "จัดการแล้ว" (หยุดเตือน) หมายถึงอะไร: (a) บันทึกฉบับต่ออายุแล้ว (E09-S04) · (b) กด "รับทราบ" · (c) ทั้งสองแบบ
- หลังรอบ 7 วัน/เลยวันหมดอายุ เตือนซ้ำถี่แค่ไหน (เช่น ทุกวัน / ทุก 3 วัน)
