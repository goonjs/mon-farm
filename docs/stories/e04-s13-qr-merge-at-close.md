# Story E04-S13: รวมข้อมูลด้วย QR ตอนปิดการขาย

Status: Draft

## Context

- Epic: `docs/epics/e04-sale-weighing.md`
- PRD: SYNC-5, D-4
- โค้ดเดิม: ไม่มี (ของใหม่) — architecture: payload QR = event ส่วนต่างของการขาย; ต้องผ่าน dependency gate (กล้อง/สแกน QR, สร้าง QR)
- ขึ้นกับ: E04-S12, E01-S09 (รับ event ซ้ำแบบ idempotent)

## คำอธิบาย

ตอนปิดการขายโดยไม่มีเน็ต เครื่องหนึ่งแสดง QR อีกเครื่องสแกน เพื่อให้ log ของการขายครบในเครื่องเดียว

## Acceptance criteria

- [ ] เครื่องหนึ่งแสดง QR ของ event การขายที่อีกเครื่องยังไม่มี; อีกเครื่องสแกนแล้วรวม (SYNC-5)
- [ ] รวมซ้ำ (สแกนซ้ำ) ไม่สร้างเข่งซ้ำ — event id เดิมรับครั้งเดียว
- [ ] ข้อมูลเกินหนึ่ง QR → แบ่งหลายภาพตามลำดับ แสดงความคืบหน้า "2/3"
- [ ] หลังรวม ยอดและเลขเข่งตรงกันทั้งสองเครื่อง
- [ ] หลังรวม รันการตรวจนับซ้ำ (E04-S14)

## Offline / sync

- ไม่ใช้เน็ต; event ที่รับผ่าน QR เข้า outbox และ sync ขึ้นตามปกติเมื่อมีเน็ต ไม่ซ้ำกับที่อีกเครื่องส่ง (idempotent)

## Test plan

- [ ] Vitest: encode/decode payload (หลายส่วน), รวม idempotent, ยอดหลังรวม
- [ ] jest-expo: จอแสดง QR หลายภาพ + ความคืบหน้า (สแกนเนอร์ปลอม)
- [ ] เครื่องจริง: สองเครื่องโหมดเครื่องบิน ชั่ง 60 เข่ง → QR → ยอดตรงกัน
