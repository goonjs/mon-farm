## ทำไม (เจ้าของ 2026-10-27)

รัน flow ปุ๋ยปัจจุบันแล้ว: หน้าตาไม่เข้ากับหน้าแรก ใช้งานยาก (วันที่เป็นช่องพิมพ์ แถวคนกรีดอัดแน่น) และ **ไม่ตรงกับงานจริง** — ของจริงคือสั่งจากร้านครั้งเดียว**หลายรายการ** เหมือนใบสั่งของ/ใบรับสินค้า แล้วค่อยมาบอกทีหลังว่ารายการไหนใส่ทำไม ใส่โซนไหน คนกรีดคนไหนรับกี่กระสอบ ให้เริ่มจากใบสั่งก่อน แล้วค่อยต่อ

## Description

สองชั้น:

1. **ใบซื้อ (ตอนสั่ง/ซื้อ)** — หน้าเดียวจบ: ร้าน (ไม่บังคับ) · วันที่ · รายการปุ๋ย (ชนิด · กระสอบ · ราคา) หลายรายการ · ผู้จ่าย/สถานะ (มีค่าเริ่มต้น) · ส่วนลดท้ายบิล (ซ่อนไว้) · บันทึก
2. **รายละเอียดทีหลัง (ต่อรายการ)** — จากใบซื้อ แต่ละรายการมี 3 เรื่องที่บอกเมื่อไหร่ก็ได้: ใส่ทำไม · ใส่ที่โซนไหน · แบ่งให้คนกรีด (กระสอบ, %, จ่ายแล้ว/ลงหนี้) แต่ละเรื่องเป็น sheet เดียวทำเสร็จในจอเดียว
3. **ของมาแล้ว** — ใบที่ "สั่งไว้" (ยังไม่ได้ของ) กดปุ่มเดียวเป็น "ได้ของแล้ว" หนี้คนกรีดเริ่มนับตอนนั้น (ตรงกับของจริง: โทรสั่งก่อน ของมาทีหลัง)

## ข้อตัดสินใจทางเทคนิค (ร่าง — solution architect เสนอ, รอเจ้าของ/ lead ยืนยัน)

- **หนึ่งใบซื้อ = ค่าใช้จ่ายหนึ่งรายการต่อหนึ่งปุ๋ย** ผูกกันด้วย `orderId` (ตัวเลือก B — items[] ในค่าใช้จ่ายเดียว — ถูกปฏิเสธ: `ExpensePatch` เป็นรายฟิลด์ สองเครื่องแก้คนละรายการจะชนกันที่ `items[]` และต้องเขียน share/debts/owed ใหม่หมด)
- เหตุผลที่เลือก: engine แบ่งหนี้/เงินที่ต้องคืน/ปัดสตางค์ทำงานต่อค่าใช้จ่ายอยู่แล้ว; conflict ต่อ head ของแต่ละรายการ; ค่าใช้จ่ายปุ๋ยเก่า (ไม่มี `orderId`) อ่านได้เหมือนใบซื้อ 1 รายการ ไม่ต้อง migrate; สต็อกต่อปุ๋ย (E10-S04) ตรงกัน
- ฟิลด์ใหม่: `ExpenseFields.orderId?`, `discountSatang?` (ส่วนลดที่จัดให้รายการนั้น), `FertilizerDetails.sacks`, `pricePerSackSatang`; ไม่มี event ชนิดใหม่
- ส่วนลดท้ายบิลจัดลงรายการด้วย largest remainder (สตางค์รวมตรงเป๊ะ) ตอนบันทึก; แก้ราคา/ลบรายการทีหลังไม่จัดใหม่เงียบ ๆ (ปุ่ม "แบ่งส่วนลดใหม่" ชัดเจนเท่านั้น)
- **"ยังไม่บอกรายละเอียด" derive ไม่เก็บ flag:** ใส่ทำไม = `reasons.length === 0`; ที่ไหน = ผลรวมโซน < กระสอบ; คนกรีด = ไม่มีคีย์ `share` (`share: null` = ตัดสินใจแล้วว่าไม่แบ่ง ต้องเขียน `null` ชัดเมื่อกด "ไม่แบ่ง")
- ความเสี่ยงที่ต้องมี test: แก้ผู้จ่าย/สถานะ/วันที่ของใบทีละรายการไม่ atomic (สองเครื่องเห็นใบที่ผู้จ่ายไม่ตรงกันชั่วคราว); ส่วนลดเพี้ยนเมื่อแก้/ลบรายการ; สองเครื่องเพิ่มรายการใน `orderId` เดียวกัน; ยอดรวม/ที่ต้องคืน/กรองต้องนับ**รายการ** ไม่นับใบซ้ำ (`ledger.ts`)

## Acceptance criteria

### A. จดใบซื้อ (ภาพ a1–a8)

- [ ] **FO-1** เข้าได้จากหน้าแรก ("ไปที่ › ซื้อปุ๋ย"), จากฟอร์มค่าใช้จ่ายเลือกหมวดปุ๋ย, และจากเพิ่มหนี้ชนิดปุ๋ย → หน้าใบซื้อเดียวกัน (ข้อมูลที่กรอกไว้พาไป: วันที่ วงจร ผู้จ่าย; ถ้าพิมพ์ยอดไว้ แถวแรกเปิดมาพร้อมยอดรวมนั้น)
- [ ] **FO-2** หน้าใบซื้อว่าง: ร้าน · วันที่ · "เพิ่มปุ๋ย"; ปุ่มบันทึกใช้ไม่ได้จนมี ≥ 1 รายการ (a1)
- [ ] **FO-3** เพิ่มรายการ: sheet "ซื้อปุ๋ยอะไร" เรียงตามที่ซื้อบ่อย พร้อมราคาครั้งก่อน; แตะ = ใส่ชนิด สูตร ยี่ห้อ ขนาดให้ครบ; "ปุ๋ยใหม่" เลือกชนิด (เคมี/ขี้ไก่-คอก/อื่น ๆ) + สูตร (จำเป็น) + ยี่ห้อ/กก. (ไม่บังคับ) + ติ๊ก "จำไว้ใช้ครั้งหน้า" เปิดไว้ก่อน (a2, a4)
- [ ] **FO-4** sheet "กี่กระสอบ ราคาเท่าไหร่": ตัวเลขกระสอบ (จำนวนเต็ม ≥ 1) กับปุ่ม − + อยู่แถวเดียว หน่วยอยู่ในกรอบเลข; ราคาเริ่มที่ "ต่อกระสอบ" (ใส่ราคาครั้งก่อนให้) สลับเป็น "ยอดรวมรายการนี้" ได้; ยอดรวมรายการคำนวณทันที (a3)
- [ ] **FO-5** ราคา/ยอดไม่ถูกต้อง (≤ 0, ว่าง) → บอกที่ช่อง ไม่ปิด sheet
- [ ] **FO-6** ใบซื้อแสดงรายการเป็นการ์ด (ไอคอน FarmMate ตามชนิด, ชื่อ, กระสอบ × ราคา, ยอด); แตะการ์ดแก้/ลบรายการ; "เพิ่มปุ๋ยอีกรายการ"; ยอดรวมทั้งใบเห็นตลอดเหนือปุ่มบันทึก (a5)
- [ ] **FO-7** บนหน้าใบซื้อมีตัวเลือกใหญ่ 2 ปุ่ม **สั่งไว้ (ยังไม่ได้ของ — ค่าเริ่มต้น) / ได้ของแล้ว** (= `committed` / `actual`; "แค่วางแผน" ไม่อยู่ใน flow ใบซื้อ ดูคำถามเปิด) และแถว "ใครจ่ายเงินไปก่อน" แสดงค่าเริ่มต้น (ผู้จ่ายครั้งก่อน, ยังไม่เคย = เงินสวน) แตะเปลี่ยนเป็นคนจากรายชื่อ/คนอื่น (a5, a7)
- [ ] **FO-8** วันที่เลือกด้วยปฏิทิน (พ.ศ.) + ปุ่มลัด วันนี้ / เมื่อวาน / 2 วันก่อน ไม่มีช่องพิมพ์ ISO; แตะวันไม่ได้ผิดรูปแบบ (a6)
- [ ] **FO-9** ร้าน: เลือกจากร้านที่เคยใช้ หรือพิมพ์ใหม่ (ไม่บังคับ, จำไว้) ใครสั่ง: ไม่บังคับ อยู่ใน sheet ร้าน
- [ ] **FO-10** "ร้านลดให้" (ส่วนลดทั้งใบ บาท) ซ่อนไว้ใน sheet ใครจ่ายเงินไปก่อน; ส่วนลด > ยอดรวม ไม่ได้; จัดลงรายการแบบ largest remainder ผลรวมสตางค์ตรงยอดสุทธิ
- [ ] **FO-11** บันทึก → เขียนค่าใช้จ่ายต่อรายการ (net หลังส่วนลด) ใน 1 ธุรกรรมของ client, ผู้จ่ายไม่ใช่เงินสวน + ซื้อแล้ว → เงินที่ต้องคืนเท่ายอดสุทธิรวม (FIN-4); จอ "บันทึกแล้ว" ให้เลือก [ใส่รายละเอียดปุ๋ย] หรือ [เสร็จ ไว้ทีหลัง] (a8) บันทึกขณะออฟไลน์ได้
- [ ] **FO-12** รายการค่าใช้จ่าย: ใบซื้อแสดงเป็น 1 แถว (ปุ๋ย N รายการ · ร้าน · วันที่ · ยอดรวม) + ป้าย "บอกรายละเอียดแล้ว x / N" แตะเปิดใบซื้อ (c1); ยอดรวม "เกิดจริง/ผูกพัน/วางแผน" นับต่อรายการ ไม่นับซ้ำ
- [ ] **FO-14** "สั่งซ้ำใบนี้" (b1): เปิดใบใหม่พร้อมรายการ จำนวน ราคาเดิม แก้ได้ (ซื้อซ้ำรายเดือน ≈ 3 แตะ แทน ≈ 15)
- [ ] **FO-13** หน้าแรก: ปุ่ม "ซื้อปุ๋ย" ใน "ไปที่"; แถวเตือน "ปุ๋ยยังไม่ได้บอกว่าใส่ที่ไหน · N รายการ" ใน "ควรรู้/ควรจัดการ" แสดงเฉพาะรายการ "ซื้อแล้ว" ที่ยังขาดข้อมูล แตะเข้าใบซื้อ (c2)

### B. รายละเอียดทีหลัง (ภาพ b0–b4)

- [ ] **FD-0** ใบที่ "สั่งไว้" แสดงปุ่มใหญ่ "ของมาแล้ว" (b0) → เปลี่ยนทุกรายการของใบเป็น `actual` ในครั้งเดียว; หนี้คนกรีด/เงินที่ต้องคืนเกิดตอนนี้ (ไม่ใช่ตอนสั่ง); หน้าแรกเตือน "ปุ๋ยที่สั่งไว้ ของมาแล้วหรือยัง" เมื่อค้างนาน (c2)
- [ ] **FD-1** หน้าใบซื้อ (b1): หัว = ยอดรวม · ซื้อแล้ว/สั่งไว้ · ผู้จ่าย · "บอกแล้ว x / N · ไม่ต้องรีบ" (เป็นแค่ข้อมูล ไม่ใช่งานค้างบังคับ); แต่ละรายการมีปุ่มใหญ่ 3 ปุ่ม (เหตุผล · ใส่ที่ไหน · คนกรีด) เขียว+ติ๊ก = บอกแล้ว, เส้นประ = ยังไม่บอก (ไม่ใช่ error)
- [ ] **FD-2** แก้ร้าน/วันที่/ผู้จ่าย/สถานะของใบจากหัวใบ → เขียนทุกรายการของใบ; ถ้ารายการในใบไม่ตรงกัน (sync ชน) แสดง "ไม่ตรงกัน" ให้เลือกค่าแล้วเขียนทุกรายการ
- [ ] **FD-3** ใส่เพื่ออะไร (sheet ของปุ่ม "เหตุผล"): เลือกหลายข้อ เรียงตามใช้บ่อย; พิมพ์ใหม่ + บันทึกไว้ใช้ซ้ำ (เหมือน S10) (b2)
- [ ] **FD-4** ใส่ที่ไหน: โซนของสวน (สวนเดียว = ไม่ต้องเลือกสวน) ต่อโซนตัวเลข − + แถวเดียว; แถบ "ใส่แล้ว x / กระสอบทั้งหมด"; ผลรวมเกินกระสอบไม่ได้; ไม่ครบก็บันทึกได้ (b3)
- [ ] **FD-5** แบ่งให้คนกรีด: การ์ดต่อคน ชื่อ − จำนวน + แถวเดียว; บรรทัดล่าง "ส่วนที่คนนั้นรับ" + ปุ่ม "% · หักตอนขายยาง / จ่ายสดแล้ว" (ถ้อยคำเสนอตามผลทดลองกับ persona — ต้องสอดคล้อง `docs/ux/glossary.md`; เดิม "ลงหนี้/จ่ายแล้ว") ค่าเริ่มต้น % จากหมวดปุ๋ย ลงหนี้; ผลรวมเกินกระสอบไม่ได้; "ไม่แบ่ง" เขียน `share: null` (b4)
- [ ] **FD-6** กระสอบที่ไม่ได้แบ่งเป็นของสวน เก็บเป็นยอดเหลือ (สต็อก E10-S04 ภายหลัง); หนี้คนกรีดเกิดเมื่อสถานะ "ซื้อแล้ว" + ลงหนี้เท่านั้น (เหมือน S10 ส่วน D)
- [ ] **FD-7** ตัวเลขการแบ่ง/ปัด/หนี้/เงินที่ต้องคืนต่อรายการเท่ากับ engine เดิมของ S10 (ไม่เขียนสูตรใหม่); แก้/ลบ/กู้คืนรายการเดียวหรือทั้งใบทำงานตาม S10 ส่วน E

- แก้ร้าน/วันที่/ผู้จ่าย/สถานะ/ส่วนลดของใบทำที่หัวใบเท่านั้น (เขียนทุกรายการ); การ์ดรายการแก้ได้เฉพาะ ชนิด กระสอบ ราคา
- ลบรายการ / แก้ราคา **ไม่จัดส่วนลดใหม่เงียบ ๆ** (ส่วนที่เหลือขึ้นเป็น "ส่วนลดที่ยังไม่ได้จัด" ให้กดแบ่งใหม่) และไม่แก้หนี้ที่ถูกหักไปแล้วตอนสรุปยอดขาย (เหมือน S10 ส่วน E)
- ปุ๋ยสูตรเดียวกันสองบรรทัดในใบเดียวได้ (นับเป็นสองรายการ)
- แก้กระสอบของรายการให้ต่ำกว่าที่แบ่งโซน/คนกรีดไปแล้ว → เตือนและไม่บันทึกจนกว่าจะแก้การแบ่ง
- ป้ายซิงก์ที่หัวจอสะท้อนสถานะจริง (ไม่ใช่ "ซิงก์แล้ว" ตายตัว)

## ไม่อยู่ใน story นี้

- รูปใบเสร็จ (ยังไม่มีอัปโหลด/คิว sync รูป) · เข้าสต็อกจริง (E10-S04) · ค่าขนส่ง/รับของไม่ครบ/จ่ายร้านภายหลังเป็นงวด (ดูคำถามเปิด) · เตือนแบบ push

## คำถามเปิดสำหรับเจ้าของ

0. **"สั่งไว้" เป็นค่าเริ่มต้น** ถูกไหม (ซื้อที่ร้านแล้วขนกลับเลย ต้องกด "ได้ของแล้ว" เอง) และ "แค่วางแผน" ต้องมีในใบซื้อไหม
1. **ร้านลดให้ (ทั้งใบ)** พอไหม หรือต้องมีส่วนลด/ค่าขนส่งต่อรายการ? (ร่างนี้: ท้ายบิลอย่างเดียว ซ่อนไว้)
2. **ซื้อแล้ว vs สั่งไว้**: "สั่งไว้" = ยังไม่จ่ายร้าน/ของยังไม่มา ใช่ไหม ต้องมีวิธีบอกว่า "จ่ายร้านแล้ว" ทีหลังไหม (ตอนนี้เปลี่ยนสถานะเป็นซื้อแล้ว)
3. **ใบเดียว ผู้จ่ายคนเดียว** ตกลงไหม (ถ้าสองคนออกเงินคนละส่วนของใบ ต้องแยกเป็นสองใบ)
4. **ค่าส่ง** และ **ติดร้านไว้ / จ่ายร้านทีหลังเป็นงวด**: ร่างนี้ "สั่งไว้" = ยังไม่จ่ายร้าน; ถ้าต้องบันทึกเป็นหนี้ร้านจริง ต้องต่อกับ "รายการที่ต้องจ่าย" (story แยก)
5. ผู้จ่ายไม่ใช่เงินสวน: ยืนยันว่าสวนต้องคืนเท่ายอดสุทธิทั้งใบ

## Offline / sync behavior

- สร้างใบ = เขียน event ค่าใช้จ่ายต่อรายการในเครื่อง (id derive/สร้างบน client) → ใช้ได้ออฟไลน์ sync อัตโนมัติ; ไม่เกิดซ้ำหลัง sync (id เสถียร: `orderId` + id รายการจาก client)
- สองเครื่องแก้คนละรายการของใบเดียว → ไม่ชน (head ต่อรายการ); แก้รายการเดียวกัน → Conflict ให้เลือก (D-30); แก้ฟิลด์ของใบ (ผู้จ่าย/วันที่/สถานะ) พร้อมกัน → รายการที่ไม่ตรงกันขึ้น "ไม่ตรงกัน" ให้เลือกค่าเดียว
- ร้าน/เหตุผล/สูตร "จำไว้" เป็น event ตั้งค่าเดิมของ S10 (ชื่อซ้ำรวมเป็นอัน)
