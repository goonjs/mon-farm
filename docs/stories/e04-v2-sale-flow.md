## Description

สร้างการขายทั้ง flow ใหม่บน v2 ตาม mockup sale v1.1.0 ทำงานออฟไลน์ทั้งหมด
ทุกการกระทำเป็น event ในบันทึกการขาย (หรือ finance log สำหรับเงิน) และอยู่ครบหลังรีโหลด
หน้าจอใช้ logic ที่มีอยู่แล้วใน `src/core` (sale-points, bridge, backfill, scale-check,
totals, settle, sale-status, compact-baht, finance/*) และ hook ของ MONEY (`use-sale-money`)

## Acceptance criteria

### ส่วน 1 — รายการการขาย (`/v2/sales`, mockup หน้า 4)

- [ ] แสดงการขายทั้งหมด ใหม่สุดก่อน บรรทัดบน "ใหม่สุดก่อน · แตะเพื่อดูสรุปการขาย"
- [ ] แถวละการขาย: วันที่ (พ.ศ.), คนรับซื้อยาง, จำนวนเข่ง, น้ำหนักรวม, สถานะ (ปิดแล้ว / กำลังชั่ง)
- [ ] ใต้แต่ละแถวบอกน้ำหนักยางของคนกรีดยางแต่ละคน คนละบรรทัด รวมกันเท่ายอดของแถว (D-78)
- [ ] ป้ายต่อแถวไม่แสดงสถานะ sync (D-65, D-70) — สถานะรวมอยู่ที่หัวแอป
- [ ] แตะแถว → เปิดการขายนั้น (ยังไม่ปิด → หน้านับเข่ง / เลือกจุด; ปิดแล้ว → การจ่ายเงิน)

### ส่วน 2 — เริ่มการขายและนับเข่ง (mockup หน้า 5–13, 2a, 2b, 2c)

- [ ] เริ่มการขาย: วันที่ (วันนี้), คนรับซื้อยาง (ใช้ล่าสุด), ผู้จัดการสวน (เติมจากข้อมูลฟาร์ม), เวลาเริ่มชั่ง (ไม่บังคับ), ราคา ฿/กก. (ใส่ทีหลังได้), น้ำหนักยางสุทธิ (ค่าเริ่มต้นของกลุ่ม) — กดถัดไปได้ทันที (E04-S02)
- [ ] เลขเข่ง: นับต่อเนื่องตามคนกรีดยาง / เริ่มนับเข่ง 1 ทุกจุด ค่าเริ่มต้นจากตั้งค่ากลุ่ม (D-53, D-79)
- [ ] ประเภทตาชั่ง: ไม่มีทศนิยม (ค่าเริ่มต้น) · ทศนิยม 1 ตำแหน่ง แสดงแต่กดไม่ได้ "ยังไม่พร้อมใช้งาน" (D-66)
- [ ] เลือกจุดชั่ง: สวน → คนกรีดยาง → จุด เลือกไว้ให้แล้ว แตะจุดเดียวก็เริ่มได้; จุดที่ยังไม่มีคนกรีดยางอยู่ในกลุ่มแยกด้านล่าง พร้อมคำเตือน (D-63, D-70 S1)
- [ ] ก่อนชั่ง: ตาชั่งอ่าน 0 ไหม? (อ่าน 0 / ไม่ใช่ 0), น้ำหนักเข่ง, น้ำหนักยางสุทธิ, "ตาชั่งควรอ่าน" = สุทธิ + น้ำหนักเข่ง (+ ค่าเบี้ยว) (E04-S03)
- [ ] 2a: ไม่ใช่ 0 → ใส่ค่าที่ตาชั่งเปล่าอ่าน แล้วเลือก "รอเปลี่ยนตาชั่ง" (หน้ารอ ตกลง กลับหน้าก่อนชั่ง ยังชั่งไม่ได้) หรือ "รับเข็มเบี้ยวและใช้ต่อ" — เก็บเป็น event (D-75)
- [ ] มีค่าเบี้ยว: ทุกที่ที่บอก "ตาชั่งควรอ่าน" รวมค่าเบี้ยวและแยกบรรทัด; ย้ายจุดต้องตรวจตาชั่งเปล่าทุกครั้ง (D-75, D-76)
- [ ] ข้ามการตรวจตาชั่งเปล่าตามโหมดในตั้งค่า (ทุกจุด / จุดแรกของสวน / ไม่ตรวจ) และบันทึกว่าข้าม (SALE-6)
- [ ] นับเข่ง (โหมดผู้บันทึก): แถวจุดชั่ง (สวน · จุด, คนกรีดยาง, ปุ่มเปลี่ยนจุด), เข่งปัจจุบันตัวใหญ่, ยอดของคนกรีดยาง (เสร็จแล้ว / น้ำหนักสะสม / เข่งไม่เต็ม), พื้นที่กดค้าง "กดค้างเพื่อบันทึกเข่งเต็ม" + ตาชั่งควรอ่าน, เครื่องมือ เข่งไม่เต็ม / ย้อนกลับ / โหมดสาธารณะ (E04-S05)
- [ ] ใส่ราคาแล้ว การ์ดแรกเป็น "ราคารวม" แบบย่อ (D-41) และ "นับแล้ว N เข่ง" ใต้เลขเข่ง
- [ ] กดค้างครบเวลา (ตั้งค่าเครื่องนี้) = 1 เข่งเต็ม; ปล่อยก่อน = ไม่นับ และบันทึกเป็นหลักฐาน (E04-S04)
- [ ] จุดที่ยังไม่มีคนกรีดยาง: แถบเตือน "จุดนี้ยังไม่มีคนกรีดยาง" ชั่งต่อได้ (D-63)
- [ ] โหมดสาธารณะ: เลขเข่งเต็มจอ แตะเพื่อกลับโหมดผู้บันทึก (E04-S07)
- [ ] 2b เข่งไม่เต็ม: แผ่นเลื่อนขึ้น ตาชั่งอ่าน ± ทีละ 1 กก. (ตามประเภทตาชั่ง), แอปหักน้ำหนักเข่ง (และค่าเบี้ยว) ให้, บอกยังขาดอีกเท่าไหร่จะเต็ม; ค่าที่อ่าน ≤ น้ำหนักเข่ง ไม่รับ; ยกเลิก = ไม่บันทึก (E04-S06, D-70 S9)
- [ ] เข่งไม่เต็มเปิดค้าง: การ์ดเข่งที่เปิดอยู่ + "จบเข่งนี้ (เข่งไม่เต็ม)"; พื้นที่กดค้างบอก "เข่ง N รอเติม"
- [ ] เปลี่ยนจุดไปจุดของคนกรีดยางคนเดิม มีเข่งเปิดอยู่ → ถาม 3 ทาง: เติมให้เต็มเข่ง · ชั่งแยกให้ครบน้ำหนักยางสุทธิ · ปล่อยเข่งไม่เต็มไว้ แล้วนับเข่งเต็มถัดไป (D-57); ไปจุดของคนกรีดยางคนอื่น → ปิดเข่งไม่เต็มเองโดยไม่ถาม (โหมดต่อเนื่อง) หรือเปิดค้างไว้ (โหมดต่อจุด) (D-70 S2)
- [ ] เติมให้เต็มเข่งที่จุดใหม่: "เติมอีก N กก." + ตาชั่งควรอ่าน; กดค้าง → ปิดเป็นเข่งเต็ม; "เติมไม่ถึง" → ใส่ค่าตาชั่ง เข่งยังเปิด
- [ ] 2c: เปิดการขายที่จุดเดิมถูกลบ → ต้องเลือกจุดใหม่ก่อนชั่งต่อ; เข่งที่ชั่งแล้วคงไว้ที่ "จุด · ลบแล้ว" (D-65, D-67)
- [ ] เมนู ⋯ มี "ชั่งครบแล้ว → ตรวจยอด" และ "บันทึกย้อนหลัง"

### ส่วน 3 — บันทึกย้อนหลัง (mockup หน้า 14, E04-S10)

- [ ] flow เดียวกับการชั่งต่อจุด (สวน → คนกรีดยาง → จุด) แล้วใส่ตัวเลข: เข่งเต็ม (เข่ง) และเข่งไม่เต็ม (กก. ยางสุทธิ ไม่บังคับ)

## Offline / sync behavior

ทุกการกระทำเขียนเป็น event ลง log ในเครื่องก่อน (IndexedDB บนเว็บ, SQLite บนมือถือ)
ไม่มีการเรียกเครือข่าย หน้าจออ่านทุกอย่างจากการ fold log จึงทำงานออฟไลน์เต็มที่และอยู่ครบหลังรีโหลด
การส่งขึ้น backend เป็นของ `src/sync` เหมือนเดิม (ปุ่ม sync pill บนหัวแอป)
เข่งจากหลายเครื่องรวมกันตามลำดับ fold (`compareEvents`) — ไม่มีอะไรเรียงตามเวลาเครื่อง
