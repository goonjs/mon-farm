## คำตอบเจ้าของ (2026-10-17)

- แชร์หลัก ๆ คือกับ**คนกรีดยาง**; เลือกได้หลายคนก็ได้ แต่ **1 รายการค่าใช้จ่ายต่อ 1 คนกรีด** (ปุ๋ย 10,000 ของคนหนึ่ง และปุ๋ย 8,000 ของอีกคน = สองรายการ)
- **ยกเลิก**การแชร์กับคนที่ไม่ใช่คนกรีด (เจ้าของ/อาจารย์/น้อง) และไม่ทำหนี้ระหว่างบุคคล
- การแบ่งเป็น**ค่าตั้งต้นของหมวด** ที่หน้าตั้งค่าหมวดค่าใช้จ่าย: เช่น ปุ๋ย = เจ้าของ 50% / คนกรีด 50%; ซ่อมแซม ตั้งแบบเดียวกันได้
- หมวดที่เปิดตัวเลือกนี้ พอบันทึกค่าใช้จ่ายที่ "เกิดจริง" ฟอร์มต้องถามว่า**คนกรีดคนไหน**รับส่วนแบ่ง
- มีสวิตช์ **"เป็นหนี้ทันที"** เปิดไว้เป็นค่าเริ่มต้น: ส่วนคนกรีดกลายเป็นหนี้คนกรีดต่อสวน (เหมือนหน้าเพิ่มหนี้) แล้วถูกหักตอนสรุปยอดขาย
- % แก้ได้ตอนบันทึกแต่ละครั้ง
- ปัดเศษเวลาหารไม่ลงตัว ต้องไม่ลืม — ผลรวมสองส่วนต้องเท่ายอดเดิมตรงสตางค์
- ใช้ได้กับทุกวงจร แต่**หนี้เกิดเมื่อเป็น "เกิดจริง"** เท่านั้น
- **ส่วนลด (เพิ่ม 2026-10-17):** บางครั้งซื้อของแล้วมีส่วนลดมาให้ ส่วนลดต้องกระจายลงไปตามสัดส่วน (%) ของแต่ละส่วนด้วย
- เจ้าของถามว่าควรลบระบบปุ๋ยแยก (E06-S01/S02/S06) ไหม — ดู "ข้อเสนอเรื่องระบบปุ๋ย" ด้านล่าง

## การตัดสินใจ (2026-10-17, เจ้าของมอบให้ทีมตัดสิน)

- **รวมแบบ 3 กับ 4:** ฟอร์มค่าใช้จ่ายทั่วไปมีช่อง "แบ่งกับคนกรีดยาง" (คนกรีด 1 คนต่อรายการ); เมื่อเลือกหมวดปุ๋ย (ที่เปิดโหมดกระสอบ) ฟอร์มพาไปหน้า "ซื้อปุ๋ย" ที่ติ๊กคนกรีดหลายคนและใส่กระสอบ (ผลรวมไม่เกินกระสอบทั้งหมด) — หน้านี้**คือฟอร์มค่าใช้จ่ายของหมวดนั้น** ไม่ใช่ระบบแยก บิลหนึ่งใบ = ค่าใช้จ่ายหนึ่งรายการ ไม่นับซ้ำ
- **ค่าเริ่มต้นที่ทีมเลือก** (เจ้าของเปลี่ยนได้): กระสอบเป็นจำนวนเต็ม; ไม่เก็บโซนในรอบแรก (YAGNI); กระสอบที่ไม่ได้แบ่งเป็นต้นทุนของสวน
- **E06-S01/S02/S06 (ระบบปุ๋ยแยก):** เสนอยกเลิกเป็น "แทนที่โดย E11-S10" — ยังไม่แก้ไฟล์เหล่านั้นจนกว่าเจ้าของยืนยัน; โค้ดหน้าเพิ่มหนี้ชนิดปุ๋ยเดิมไม่ลบ
- **ส่วนลด:** ใส่เป็นบาท; แบ่งตามสัดส่วนเดียวกับต้นทุน (ยอดสุทธิ = ยอดบิล − ส่วนลด)
- ภาพประกอบ: `docs/ux/mockups/flow-expense-share-v1.3.0.html`

## Acceptance criteria — หน้าซื้อปุ๋ย (เพิ่มจากข้อกำหนดข้างบน)

- [ ] หมวดที่เปิด "ซื้อแบบแบ่งกระสอบ": เลือกหมวดแล้วฟอร์มพาไปหน้าซื้อปุ๋ย ยอดบิลและวันที่ที่กรอกไว้ถูกพาไปด้วย
- [ ] หน้าซื้อปุ๋ยแสดงคนกรีดทุกคนเป็นการ์ด ติ๊กเลือกผู้ร่วมรับ; ติ๊กแล้วใส่จำนวนกระสอบ (จำนวนเต็ม ≥ 1); ผลรวมเกินกระสอบทั้งหมดไม่ได้ และแสดงจำนวนที่แบ่งแล้ว/เหลือ
- [ ] ต้นทุนต่อคน = ยอดสุทธิ × (กระสอบของคน ÷ กระสอบทั้งหมด) ปัดเป็นสตางค์แล้วจัดเศษให้ผลรวมเท่ายอดสุทธิเสมอ; หนี้ = ต้นทุน × % คนกรีดรับ (ใช้ `fertilizerSplit`); ส่วนที่เหลือรวมกระสอบที่ไม่ได้แบ่งเป็นของสวน
- [ ] การ์ดคนกรีด: ติ๊กร่วม, กระสอบ (+ ปุ่ม "ใช้ที่เหลือทั้งหมด"), % เฉพาะคน (เริ่มจากหมวด), ต้นทุนและหนี้ (อ่านอย่างเดียว), สวิตช์เป็นหนี้ทันทีของคนนี้, หมายเหตุ
- [ ] บันทึกเป็นค่าใช้จ่ายหนึ่งรายการ (ยอดเต็ม) + หนี้ต่อคน (เมื่อเกิดจริงและสวิตช์เปิด); ยอด "เกิดจริง" ไม่เพิ่มจากหนี้

## Description

หมวดค่าใช้จ่ายตั้งสัดส่วนเจ้าของ/คนกรีดไว้ได้ ตอนบันทึกค่าใช้จ่ายในหมวดนั้น เลือกคนกรีดที่รับส่วนแบ่ง
ระบบคำนวณส่วนคนกรีดและส่วนเจ้าของ (รวมแล้วเท่ายอดเดิม) และสร้างหนี้คนกรีดให้ทันทีถ้าเปิดสวิตช์

## Acceptance criteria

- [ ] หน้าตั้งค่าหมวด: หมวดเปิด "แบ่งกับคนกรีดยาง" ได้ และตั้ง % ของคนกรีด (จำนวนเต็ม 0–100; ส่วนเจ้าของ = เหลือ) ค่าเริ่มต้นของหมวดปุ๋ยจากเจ้าของ = 50/50 (ตั้งเอง ไม่ฝังโค้ด)
- [ ] ฟอร์มค่าใช้จ่ายของหมวดที่เปิดตัวเลือก: แสดงตัวเลือกคนกรีด (เลือก 1 คน) + ช่อง % (ค่าตั้งต้นจากหมวด แก้ได้) + สวิตช์ "เป็นหนี้ทันที" (เปิดเป็นค่าเริ่มต้น) + พรีวิว "คนกรีด X บาท · เจ้าของ Y บาท"
- [ ] ส่วนคนกรีด = ยอด × % ปัดครึ่งขึ้นเป็นสตางค์ (ใช้ `fertilizerSplit`); ส่วนเจ้าของ = ยอด − ส่วนคนกรีด → ผลรวมเท่ายอดเดิมเสมอ (เช่น 100.01 บาท × 50% → คนกรีด 50.01 / เจ้าของ 50.00)
- [ ] **ส่วนลด:** ฟอร์มของหมวดที่แบ่งได้มีช่อง "ส่วนลด" ใส่เป็นบาท (ไม่บังคับ; เจ้าของตอบ 2026-10-17); ยอดสุทธิ = ยอดบิล − ส่วนลด; การแบ่งคนกรีด/เจ้าของคิดจากยอดสุทธิ จึงเท่ากับกระจายส่วนลดตามสัดส่วนเดียวกับ % ที่แบ่ง; ส่วนลดมากกว่ายอดบิลไม่ได้; ผลรวมสองส่วน = ยอดสุทธิตรงสตางค์ (ใช้ `fertilizerSplit` กับยอดสุทธิ); ยอดค่าใช้จ่าย "เกิดจริง" ที่นับคือยอดสุทธิ และเก็บยอดบิลกับส่วนลดแยกฟิลด์ไว้ดูย้อนหลัง (FIN-1)
- [ ] ไม่เลือกคนกรีด = บันทึกค่าใช้จ่ายเต็มจำนวนตามเดิม ไม่แบ่ง ไม่มีหนี้ (ไม่บังคับ — ฟอร์มยังบังคับแค่จำนวนเงิน + วันที่, D-62)
- [ ] วงจร **เกิดจริง** + สวิตช์เปิด + มีคนกรีด → สร้างหนี้คนกรีดต่อสวนเท่าส่วนคนกรีด โผล่ในหน้าจัดการหนี้ของคนนั้น และเข้ากลไกหักตอนสรุปยอดขายเดิม (E06-S04) โดยไม่แก้กลไกนั้น
- [ ] วงจร **ผูกพันแล้ว/วางแผน**: เลือกคนกรีดและ % ล่วงหน้าได้ แต่ **ยังไม่สร้างหนี้** — สร้างเมื่อเลื่อนเป็นเกิดจริง (สอดคล้อง E11-S02); วางแผนที่จำนวนเงิน "ไม่ทราบ" ยังไม่มีส่วนแบ่งจนกว่าจะใส่จำนวนเงิน
- [ ] สวิตช์ปิด = บันทึกส่วนแบ่งไว้เฉย ๆ ไม่สร้างหนี้
- [ ] **ไม่นับซ้ำ**: ค่าใช้จ่ายเก็บยอดเต็มเป็นรายการเดียว; หนี้ที่สร้างอ้างถึงค่าใช้จ่ายนั้น และ**ไม่**สร้างรายการ "ส่วนเจ้าของ" ซ้ำอีกชั้น (ต่างจากหน้าเพิ่มหนี้ชนิดปุ๋ยที่สร้างค่าใช้จ่ายส่วนเจ้าของเอง) — ยอดรวม "เกิดจริง" ไม่เพิ่ม
- [ ] แก้จำนวนเงิน/%/คนกรีด/สวิตช์/วงจร ภายหลัง → หนี้ที่เชื่อมปรับตามพร้อมประวัติ; ลบค่าใช้จ่าย → หนี้ที่เชื่อมถูกยกเลิก (กู้คืน → กลับมา); หนี้ที่ถูกหักไปแล้วบางส่วนแล้วยอดลดต่ำกว่าที่หัก → ขึ้นสถานะให้เจ้าของแก้ ไม่ปรับเงียบ ๆ (ตาม D-61)
- [ ] เงินเก็บเป็นสตางค์จำนวนเต็ม ไม่มี float (NFR-3); เห็นเฉพาะสมาชิกกลุ่ม (NFR-5)
- [ ] ป้ายคำไทยชัด ทุกสถานะมีข้อความ ไม่พึ่งสีอย่างเดียว; UI ใช้ `src/ui` ตาม design system

## ข้อเสนอเรื่องระบบปุ๋ยแยก (E06-S01 / S02 / S06) — รอเจ้าของยืนยัน

ทั้งสาม story ยังเป็น Draft ไม่ได้สร้างโค้ด เสนอ**ไม่สร้าง**ระบบปุ๋ยแยก:

- S01 บันทึกการซื้อปุ๋ย → ทำที่หน้าค่าใช้จ่ายหมวดปุ๋ยแทน (story นี้)
- S02 แบ่งภาระ 50/50 → ตั้งที่หมวด (story นี้)
- S06 แผนปุ๋ย → ค่าใช้จ่ายวงจร "วางแผน" ที่มีอยู่แล้ว (E11-S01)
- **สิ่งที่หายไป:** การแบ่งตาม**จำนวนกระสอบ**ต่อคนกรีด (ปัจจุบันเป็น % ต่อรายการ 1 คนต่อ 1 รายการ) — ไม่ทำ (YAGNI) เว้นแต่เจ้าของต้องการ
- หน้าเพิ่มหนี้ชนิดปุ๋ย (`/v2/debt-add`) ที่มีอยู่แล้วยังคงไว้สำหรับยอดยกมา/เพิ่มหนี้มือ (E06-S03) — ไม่ลบโค้ดใด ๆ ใน story นี้
- การเปลี่ยนสถานะ/ยกเลิก E06-S01/S02/S06 ทำเมื่อเจ้าของยืนยัน ไม่แก้ไฟล์เหล่านั้นก่อน

## Offline / sync behavior

- ส่วนแบ่ง/คนกรีด/สวิตช์ เป็นฟิลด์ของ event ค่าใช้จ่ายเดียวกัน; หนี้ที่เชื่อมเป็น projection ในเครื่องจาก event ค่าใช้จ่าย (เหมือน E11-S02) → ใช้ได้ออฟไลน์, ไม่สร้างซ้ำหลัง sync (id ของหนี้ derive จาก id ค่าใช้จ่าย)
- สองเครื่องแก้ % หรือคนกรีดของรายการเดียวกัน → Conflict ตาม E11-S01 (D-30) ไม่ทับเงียบ
- ตั้งค่าสัดส่วนของหมวดเป็น event ของหมวด (`category_*`) — ออฟไลน์ได้ รวมตามกฎเดิม

## Test plan

_เขียนให้ fail ก่อน (TDD)_

- [ ] Unit: ตัวแบ่ง — ผลรวมสองส่วน = ยอดเดิม ทุกเคส (0%, 100%, 33%, สตางค์คี่, ยอดเล็ก 1 สตางค์) ใช้ `fertilizerSplit`

- [ ] Unit: ค่าใช้จ่ายเกิดจริง + สวิตช์เปิด → มีหนี้ 1 รายการเท่าส่วนคนกรีด; สวิตช์ปิด/ไม่เลือกคน/ผูกพัน/วางแผน → ไม่มีหนี้; เลื่อนเป็นเกิดจริง → มีหนี้
- [ ] Unit: ไม่นับซ้ำ — ยอดเกิดจริงรวม = ยอดเต็มของค่าใช้จ่าย ไม่เพิ่มเพราะมีหนี้
- [ ] Unit: แก้ยอด/%/คนกรีด → หนี้ปรับ; ลบ/กู้คืนค่าใช้จ่าย → หนี้ยกเลิก/กลับมา; หักไปแล้วเกินยอดใหม่ → สถานะให้แก้
- [ ] Component: ฟอร์มหมวดที่เปิดตัวเลือกแสดงคนกรีด/%/สวิตช์/พรีวิว; หมวดอื่นไม่แสดง; ฟอร์มยังบันทึกได้ด้วยจำนวนเงิน + วันที่เท่านั้น
- [ ] Component: หน้าตั้งค่าหมวด เปิด/ปิดและตั้ง %; ค่าไม่ใช่จำนวนเต็ม 0–100 ถูกปฏิเสธ
- [ ] Integration: หนี้ที่สร้างโผล่ในหน้าจัดการหนี้ และถูกหักตอนสรุปยอดขายได้ (ผ่านกลไก E06-S04 เดิม)
- [ ] Offline: สองเครื่องบันทึก/แก้แล้ว sync — ไม่เกิดหนี้ซ้ำ; แก้ % พร้อมกัน → Conflict
