## ทำไม (เจ้าของ)

ปุ๋ยสำคัญ: ใช้ติดตามเทียบกับผลผลิต ติดตามราคาปุ๋ย รู้ว่าใส่อะไร เพิ่มอะไร เพราะอะไร
ต่อไปอาจทำคำแนะนำ "เกิดสิ่งนี้ ควรใส่อะไร" ได้ และส่วนแบ่งกับคนกรีดต้องไปหักหนี้ตอนสรุปยอดขายเองอัตโนมัติ

ปัญหาตอนนี้: มีหน้าบันทึกปุ๋ย (หนี้ชนิดปุ๋ย) อยู่แล้ว แต่พอบันทึกรายจ่ายแล้วเลือกปุ๋ย หน้าตาไม่เหมือนกัน

## คำสั่งเจ้าของ (2026-10-18)

- หน้าบันทึกค่าใช้จ่ายมี "แชร์ค่าใช้จ่าย" กับคนกรีดยาง และเลือกให้เป็นหนี้ทันทีได้
- ค่าใช้จ่ายที่เกิดขึ้นแล้ว ต้องเลือกว่า**ใครจ่ายไปก่อน** เพื่อลงถูกบัญชี
- เลือกหมวดปุ๋ยแล้ว ใช้ **component และ flow เดียวกับหน้าบันทึกหนี้ปุ๋ย**
- สัดส่วนตั้งที่หมวดค่าใช้จ่าย (เช่น ปุ๋ย เจ้าของ 50 / คนกรีด 50; ซ่อมแซมตั้งแบบเดียวกันได้); แก้ % ได้ทุกครั้งที่บันทึก
- ส่วนของคนกรีดเป็นหนี้คนกรีดต่อสวน (เหมือนหน้าเพิ่มหนี้) แล้วหักตอนสรุปยอดขาย
- ใช้ได้ทุกวงจร แต่หนี้เกิดเมื่อเป็น "เกิดจริง" เท่านั้น
- ส่วนลดใส่เป็นบาท; ยอดสุทธิ = ยอดบิล − ส่วนลด; แบ่งตามสัดส่วนเดียวกับต้นทุน
- ปัดเศษ: ผลรวมเท่ายอดสุทธิตรงสตางค์ (`fertilizerSplit`)
- กระสอบเป็นจำนวนเต็ม
- ปุ๋ยกรอกตาม spec (FERT-1) รวมชนิดปุ๋ย และเพิ่ม**สาเหตุที่ใส่**: เลือกได้หลายข้อ, พิมพ์เองได้ พร้อมปุ่มบันทึกไว้ใช้ซ้ำ, มี setting ปุ๋ยโดยเฉพาะไว้เพิ่มตัวเลือกสาเหตุ
- flow แบ่งเป็นขั้น: ซื้อ → โซน (ไม่บังคับ) → คนกรีด → สรุป (รายละเอียดใน AC ส่วน C)
- กระสอบที่เหลือจากการแบ่ง ถือว่าเก็บเข้าสต็อก — เพิ่ม story ไว้ (E10-S04) ยังไม่ทำ

## Acceptance criteria

### A. ใครจ่ายไปก่อน (ค่าใช้จ่ายที่เกิดจริงทุกหมวด)

- [ ] วงจร "เกิดจริง" มีช่อง **ใครจ่ายไปก่อน**: เงินสวน หรือบุคคลจากรายชื่อคน; ค่าเริ่มต้น = **คนเดิมของครั้งก่อน** (ยังไม่เคยบันทึก = เงินสวน) (เจ้าของ 2026-10-18, ตรง D-62)
- [ ] ผู้จ่ายไม่ใช่เงินสวน → สร้าง **เงินที่สวนต้องคืน** คนนั้นเท่ายอดสุทธิ (FIN-4) แยกจากหนี้คนกรีด

### B. หมวดทั่วไปที่ตั้งสัดส่วนไว้ (เช่น ซ่อมแซม)

- [ ] หน้าตั้งค่าหมวด: เปิด "แชร์กับคนกรีดยาง" และตั้ง % คนกรีด (จำนวนเต็ม 0–100; เจ้าของ = ที่เหลือ) ไม่ฝังค่าในโค้ด
- [ ] ฟอร์มค่าใช้จ่ายของหมวดนั้น: เลือกคนกรีด + % (ค่าจากหมวด แก้ได้) + ส่วนลด (บาท ไม่บังคับ) + "จ่ายแล้ว / ลงหนี้" (ค่าเริ่มต้น ลงหนี้) + พรีวิว "คนกรีด X · เจ้าของ Y"
- [ ] ไม่เลือกคนกรีด = บันทึกเต็มจำนวนตามเดิม; หมวดที่ไม่เปิด ไม่แสดงตัวเลือกนี้

### C. ปุ๋ย — flow 6 ขั้น (ชุดเดียวกับหน้าบันทึกหนี้ปุ๋ย)

- [x] เลือกหมวดปุ๋ยในหน้าค่าใช้จ่าย **หรือ** เลือกหนี้ชนิดปุ๋ยในหน้าเพิ่มหนี้ → เข้า flow เดียวกัน (component เดียว); ข้อมูลที่กรอกไว้ถูกพาไปด้วย; บอกขั้น 1/6–6/6; ย้อนกลับไม่หายข้อมูล
- [x] หน้าจอใดยาวเกินไป แบ่งเป็นขั้นย่อยได้ถ้า UX ดีกว่า (เจ้าของ 2026-10-18) — จำนวนขั้นสุดท้ายตาม mockup ที่อนุมัติ
- [x] ขั้นตาม mockup 7b: 1 ซื้ออะไร (ชนิด กระสอบ ราคา ส่วนลด ยอดสุทธิ) → 2 ทำไม (สาเหตุ) → 3 ใครจ่าย · เมื่อไร (วันที่ วงจร ผู้จ่าย ร้าน/ใครสั่ง/รูป) → 4 โซน → 5 คนกรีด → 6 สรุป; ฟอร์มค่าใช้จ่ายทั่วไปย่อการแชร์เป็นบรรทัดเดียว กดแล้วเปิดหน้าแชร์
- [ ] **ข้อมูลการซื้อ:** ชนิดปุ๋ย (เคมี / ขี้ไก่ / อื่น ๆ ตาม FERT-1 + ชื่อ/สูตร พิมพ์ได้), จำนวนกระสอบ (จำนวนเต็ม ≥ 1), ราคา, ส่วนลด (บาท), ยอดสุทธิ (คำนวณ), วันที่, วงจร, ใครจ่ายไปก่อน (A), สาเหตุที่ใส่, ร้าน / ใครสั่ง / รูปใบเสร็จ (ไม่บังคับ, FERT-1) — ครบยกเว้นรูปใบเสร็จ (ยังไม่มีอัปโหลดรูป ดู Dev notes)
- [x] **รายละเอียดสินค้า:** สูตร/ชื่อปุ๋ย, ยี่ห้อ, ขนาดกระสอบ (กก./กระสอบ) — พิมพ์ได้ และค่าที่พิมพ์เพิ่มเป็นตัวเลือกที่บันทึกไว้ได้เรื่อย ๆ (เพิ่มตรงนั้นเลย หรือในตั้งค่าปุ๋ย) เพื่อเก็บข้อมูลให้สม่ำเสมอไว้ติดตามภายหลัง (เจ้าของ 2026-10-18)
- [x] **สาเหตุ:** เลือกได้หลายข้อ; แต่ละสาเหตุมีชื่อ + คำอธิบาย (ไม่บังคับ) อ่านเพิ่มได้ทีละรายการ ไม่กางทั้งหมด; มีช่องค้นหา; แสดงเป็นรายการ (ไม่ใช่ chips) เพื่อรองรับจำนวนมาก; พิมพ์สาเหตุใหม่ (พร้อมคำอธิบาย) ได้ทันที + "บันทึกไว้ใช้ซ้ำ" (ไม่กด = ใช้ครั้งนี้ครั้งเดียว) (เจ้าของ 2026-10-18)
- [x] **ตั้งค่าปุ๋ย** (หน้าใหม่): เพิ่ม / แก้ / ซ่อน สาเหตุ (ชื่อ + คำอธิบาย) และตัวเลือกสูตร / ยี่ห้อ / ขนาดกระสอบ; ซ่อนแล้วรายการเก่ายังแสดงชื่อเดิม
- [x] **โซน:** ต้องมีโซนจริงก่อน — ทำ E03-S04 (สร้าง/แก้โซนของสวน) ในงานนี้ ก่อนขั้นโซนของ flow
- [x] **ขั้น 4 โซน (ไม่บังคับ):** การ์ดต่อโซน ใส่กระสอบ + เลือกสาเหตุ (จากที่เลือกในขั้น 2) + โน้ต; ผลรวมไม่เกินกระสอบทั้งหมด; ไปต่อได้โดยไม่กรอก พร้อมข้อความ "บันทึกภายหลังได้"
- [x] **ขั้น 5 คนกรีด:** การ์ดคนกรีด เลือกคน แล้วใส่กระสอบที่รับ; การ์ดคำนวณ ราคารวมของคนนั้น (ยอดสุทธิ × กระสอบ ÷ กระสอบทั้งหมด) และส่วนที่คนกรีดรับ (× % แก้ได้ต่อคน); ต่อคนเลือก **"จ่ายแล้ว"** หรือ **"ลงหนี้"**; แสดง "แบ่งแล้ว / เหลือ" ตลอด
- [x] คนกรีด**คนสุดท้าย**ถูกเติมกระสอบที่เหลือทั้งหมดให้เอง แก้ได้; ผลรวมเกินกระสอบทั้งหมดไม่ได้
- [x] กระสอบที่เหลือ: ต้นทุนเป็นของสวน + ป้าย "เหลือ N กระสอบ เก็บเข้าสต็อก" (เข้าสต็อกจริงใน E10-S04; รอบนี้เก็บจำนวนไว้)
- [x] **ขั้น 6 สรุป:** เห็นง่าย กระชับ ครบ — บรรทัดหลัก (ชนิด · กระสอบ · ยอดสุทธิ · ใครจ่าย), การแบ่ง เจ้าของ / คนกรีด / เหลือ, รายคนกรีด (กระสอบ · ส่วน · จ่ายแล้ว/ลงหนี้); ส่วนที่ยาว (โซน, สาเหตุ, ร้าน, รูป) ย่อไว้ กดดูเป็น sheet/modal; แก้แต่ละขั้นได้; ปุ่มบันทึก (UX ออกแบบรายละเอียด)
- [x] บันทึก = ค่าใช้จ่าย **1 รายการ** (ยอดสุทธิ + ยอดบิล/ส่วนลด/ชนิด/กระสอบ/สาเหตุ/โซน/การแบ่ง) + หนี้ต่อคนที่ "ลงหนี้" (เมื่อเกิดจริง) + เงินที่ต้องคืน (ถ้าผู้จ่ายไม่ใช่เงินสวน)

### D. ตัวเลข

- [ ] ราคาต่อคนปัดเป็นสตางค์แล้วจัดเศษ: รวมทุกคน + ส่วนที่เหลือ = ยอดสุทธิเสมอ; ส่วนคนกรีด = `fertilizerSplit(ราคาคนนั้น, %)`; เงินเป็นสตางค์จำนวนเต็ม (NFR-3)
- [x] **ส่วนลด** เป็นสวิตช์ "มีส่วนลด" ปิดไว้ก่อน (เห็นชัด หาไม่ยาก) เปิดแล้วจึงแสดงช่องบาทและยอดสุทธิ; อยู่**ก่อน**ส่วนแบ่ง (คนกรีด/%) ทั้งในหน้าแชร์และขั้นซื้อปุ๋ย (เจ้าของ 2026-10-18)
- [ ] ส่วนลด > ยอดบิล ไม่ได้
- [ ] **ไม่นับซ้ำ:** ยอด "เกิดจริง" รวม = ยอดสุทธิของรายการ ไม่เพิ่มเพราะมีหนี้; บันทึกจากหน้าเพิ่มหนี้หรือหน้าค่าใช้จ่ายได้ผลเท่ากัน
- [ ] วงจรผูกพันแล้ว/วางแผน: กรอกการแบ่งล่วงหน้าได้ แต่ยังไม่มีหนี้ / เงินที่ต้องคืน — เกิดเมื่อเลื่อนเป็นเกิดจริง

### E. แก้ / ลบ / กู้คืน

- [ ] แก้ยอด / % / กระสอบ / คนกรีด / จ่ายแล้ว-ลงหนี้ / วงจร → หนี้และเงินที่ต้องคืนที่เชื่อมปรับตาม พร้อมประวัติ
- [ ] ลบ → หนี้และเงินที่ต้องคืนที่เชื่อมถูกยกเลิก; กู้คืน → กลับมา
- [ ] หนี้ที่ถูกหักตอนสรุปยอดขายไปแล้ว แล้วยอดใหม่ต่ำกว่าที่หัก → ไม่ปรับเงียบ ขึ้นสถานะให้เจ้าของแก้

## Offline / sync behavior

- การซื้อ การแบ่ง โซน สาเหตุ อยู่ใน event ค่าใช้จ่ายเดียว; หนี้และเงินที่ต้องคืนเป็น projection ในเครื่อง id derive จากค่าใช้จ่าย → ออฟไลน์ได้ ไม่เกิดซ้ำหลัง sync
- สองเครื่องแก้รายการเดียวกัน → Conflict ไม่ทับเงียบ
- สาเหตุที่บันทึกไว้ใช้ซ้ำ และ % ของหมวด เป็น event ตั้งค่า ออฟไลน์ได้; สองเครื่องเพิ่มสาเหตุชื่อเดียวกัน → รวมเป็นอันเดียว
- รูปใบเสร็จเข้าคิวอัปโหลดตอน sync
