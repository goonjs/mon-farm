## คำอธิบาย

ชีต "เข่งไม่เต็ม" ตอนนี้บังคับให้อ่านค่าตาชั่งบนหน้าปัดอย่างเดียว เพิ่มทางเลือก 2 ข้อ

1. ตั้งค่าเครื่อง เลือกโหมดบันทึกว่าจะใช้ **พิมพ์ตัวเลข** หรือ **หน้าปัด**
2. โหมดหน้าปัด เลือกฐานได้ว่าจะเลื่อนตาม **ตาชั่งอ่าน** (ไอคอนตราชั่ง) หรือ **ยางสุทธิ** (ไอคอนใบไม้)
3. โหมดพิมพ์ตัวเลข มี 2 ช่องชัดเจน (ตาชั่งอ่านได้ / ยางสุทธิ) กรอกช่องไหนก็ได้ อีกช่องคำนวณให้ทันที

เป็นเรื่องวิธีกรอกเท่านั้น ค่าที่บันทึกยังเป็น event `short` เดิมด้วย `readingG` เท่าเดิม (ยางสุทธิ = ตาชั่งอ่าน − น้ำหนักเข่ง − skew − ยางที่มีอยู่เดิมตอนเติมเข่ง)

## Acceptance criteria

- [x] ตั้งค่าเครื่อง (`/v2/device`) มีตัวเลือก "วิธีบันทึกเข่งไม่เต็ม": พิมพ์ตัวเลข | หน้าปัด **ค่าเริ่มต้น พิมพ์ตัวเลข** (เจ้าของ 2026-10-13); เป็นค่าของเครื่อง ไม่ sync ไม่อยู่ใน event log
- [x] โหมดหน้าปัด: มีปุ่มสลับ "ตาชั่งอ่าน" (ตราชั่ง) / "ยางสุทธิ" (ใบไม้) ที่หัวชีต ค่าเริ่มต้น "ตาชั่งอ่าน" และจำค่าล่าสุดไว้ในเครื่อง
- [x] ฐาน "ตาชั่งอ่าน": เลขใหญ่ หน้าปัด ขีด "ตาชั่งควรอ่าน" เหมือนเดิมทุกอย่าง
- [x] ฐาน "ยางสุทธิ": เลขใหญ่ หน้าปัด ± ทีละ 1 กก. และขีดเป็นน้ำหนักยางสุทธิ (ขีดป้าย "ยางควรได้") ส่วนการ์ดอีกค่าแสดง "ตาชั่งจะอ่าน"
- [x] สลับฐานแล้วค่าจริงไม่เปลี่ยน (ตาชั่ง 37 กก. เข่ง 2 กก. ↔ ยางสุทธิ 35 กก.)
- [x] โหมดพิมพ์: 2 ช่อง "น้ำหนักที่ตาชั่งอ่านได้ (รวมเข่ง)" ไอคอนตราชั่ง และ "น้ำหนักยางสุทธิ" ไอคอนใบไม้; พิมพ์ช่องไหนก็ได้ ช่องนั้นขึ้น "กำลังกรอก" อีกช่องขึ้น "คำนวณให้" ทันทีที่พิมพ์ เลขชิดขวาติดหน่วย กก.
- [x] โหมดพิมพ์รับตัวเลขและจุดทศนิยมเท่านั้น; ช่องว่างหรือยางสุทธิ ≤ 0 บันทึกไม่ได้ และบอกเหตุผล; เกินเต็มเข่งแสดงเตือนสีเหลืองแต่บันทึกได้ (เหมือนหน้าปัดเดิม)
- [x] แถบ "ยังขาด … จึงเต็ม …" แสดงทั้งสองโหมด; ที่มี skew หรือยางเดิมยังแสดงรายการหักเหมือนเดิม
- [x] event ที่บันทึกเหมือนกันทุกโหมด: ตาชั่ง 37 → `readingG: 37000` ไม่ว่ากรอกจากช่องไหน
- [x] สีไม่ใช่ตัวบอกสถานะอย่างเดียว (ไอคอน + ป้ายคำ) และ target ≥ ขนาดต่ำสุดของ token

## Offline / sync

- เป็นค่าของเครื่อง เก็บใน localStorage เหมือน hold-preference ไม่เข้า outbox ไม่ sync ใช้ได้ออฟไลน์เต็มที่
