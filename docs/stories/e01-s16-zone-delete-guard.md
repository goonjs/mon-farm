# Story E01-S16: ลบเขตไม่ได้ถ้าคนกรีดของเขตยังมียอดหัก

Status: Review

## Context

- Epic: `docs/epics/e01-foundation-sync.md`
- PRD: SYNC-10 · **D-44** (เจ้าของ 2026-10-03, คำถาม D6 = ตัวเลือก a)
- ต่อจาก: E01-S04 (Soft Delete) — finding #5 ของ review: ลบเขตแล้วรายการหักของคนกรีดเขตนั้นยังอยู่ ยอดจ่ายติดลบได้
- เกี่ยวข้อง: D-18 (หักไม่เกินส่วนแบ่ง — E06)

## คำอธิบาย

การลบเขต (โซน) ที่คนกรีดตามสัญญาของเขตนั้นยังมีรายการหักในการขายนี้ ต้องถูกขวางพร้อมบอกว่ารายการหักไหนขวาง
ผู้ใช้ต้องยกเลิกรายการหักเหล่านั้นก่อนจึงลบเขตได้ — ใช้แม้คนกรีดคนนั้นมีเขตอื่นอยู่ด้วย (ตามถ้อยคำ D-44 และปลอดภัยจนกว่า
D-18 "หักไม่เกินส่วนแบ่ง" จะมีใน E06) ด้านกลับกันก็ถูกขวาง: กู้คืนรายการหักของคนกรีดในเขตที่ถูกลบไม่ได้จนกว่าจะกู้คืนเขต
ก่อน กติกาอยู่ที่ `src/core/delete-guard.ts` และทุกทางเขียนเรียกตัวเดียวกัน (`setDeleted` และ `SaleProvider.append`)
เพื่อให้หน้าจอลบเขตที่จะมาใน E03/E04 ใช้ตัวเดียวกันไม่ว่าจะเขียนผ่านทางไหน "สวน" (ที่ดิน) ยังไม่มีในโมเดล — ใช้กติกาเดียวกันเมื่อสร้างใน E03-S02

## Acceptance criteria

- [x] ลบเขตไม่ได้ถ้าคนกรีดตามสัญญาของเขตนั้นมีรายการหักที่ยังมีผล (ไม่ถูกยกเลิก ไม่ถูกลบ) ในการขายนี้ — คืนรายการหักที่ขวาง
- [x] ยกเลิก (void) หรือลบรายการหักเหล่านั้นแล้ว → ลบเขตได้
- [x] บังคับที่ทุกทางเขียน (`setDeleted` และ `SaleProvider.append`) — ไม่มี event ถูกเขียนเมื่อถูกขวาง
- [x] เทสต์ของ E01-S04 ที่ตรึงว่ายอดจ่ายติดลบได้ ถูกแทนด้วยเทสต์ของกติกานี้
- [x] event `delete` ของเขตที่มาจากที่อื่นแล้ว (เครื่องเก่า / ก่อนกติกา) ยังโปรเจกต์ได้ ไม่ crash — การจัดการขัดกันอยู่ใน E01-S11

## Offline / sync behavior

- ตรวจกับ log ในเครื่องล้วน ทำงานออฟไลน์ได้
- อีกเครื่องเพิ่มรายการหักขณะเครื่องนี้ลบเขตแบบออฟไลน์ → ไม่ถูกขวางในเครื่องนี้ (ไม่รู้) — เป็นกรณีของ E01-S11
- นอกขอบเขต: ลบ**กอง**ในเขตทำให้ส่วนแบ่งลดลงจนต่ำกว่ารายการหักได้ — เป็นเรื่องของ D-18 (หักไม่เกินส่วนแบ่ง) ใน E06
  ไม่ใช่ D-44; ลบทั้ง**การขาย**ไม่ใช่ทางเลี่ยง เพราะการขายและสรุปเงินถูกซ่อนไปด้วยกัน
