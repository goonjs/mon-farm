ปิดการขาย: สรุปจ่ายเงินคนกรีด + หักหนี้คืน

PROPOSAL (ร่าง · รอเจ้าของเลือก · ยังไม่แตะโค้ดแอป) · ออกแบบจากการรันแอปจริงที่ 390×844 · ใช้วิธีเดียวกับใบซื้อปุ๋ย (E11-S11): ถามทีละเรื่อง ใส่ค่าเริ่มต้นให้ ของรองซ่อนไว้แต่หาเจอ แป้นตัวเลขในแอป · เงินทุกบรรทัดในหน้านี้คำนวณและตรวจให้รวมเท่ายอดขายถึงสตางค์แล้ว

1 · วันนี้เป็นอย่างไร (build จริง)

ตัวอย่าง: ขาย 550 กก. × 52.50 = 28,875.00 · แดง ส่วนแบ่ง 9,187.50 ติดเงินยืม 2,000 · นัด ส่วนแบ่ง 5,250.00 ติดค่าปุ๋ย 7,350 และสวนติดนัด 640 · ปัดเศษมี 0.50

ที่เจอตอนรันแอปจริง (390×844 · build จาก dev)รายละเอียด
ยาวและซ้ำหน้า "สรุปยอดส่วนแบ่ง" ยาว 2.3 จอ (หลังหักหนี้ 2.6 จอ) แบ่ง ก/ข/ค ตัวเลขชุดเดิม (ขายได้ / ส่วนแบ่ง / เงินสดที่ต้องจ่าย) โผล่ซ้ำ 4–5 ครั้งตลอด 5 จอ — ที่เจ้าของอยากรู้จริง ๆ คือ "ฉันต้องจ่ายเงินสดใครเท่าไหร่" อยู่กลางหน้า
หักหนี้ = 3+ แตะต่อคนกด "หักเงินคืนหนี้" → sheet สูง 1.6 จอ → เลื่อนหาปุ่มบันทึก (อยู่ลึกสุด ที่ y≈1,230 บนจอสูง 844) · ยอดที่แอปเสนอถูกอยู่แล้ว (หักเต็มไม่เกินส่วนแบ่ง) แต่ต้องเปิด-บันทึกทุกคน และคนที่ถูกลืมอยู่ในกล่อง "ยังไม่ได้หักหนี้" ใต้จอ
แก้ยอดหักยากช่องพิมพ์ใช้แป้นพิมพ์เครื่อง + ปุ่ม − + (ครั้งละ 100) — แบบที่เจ้าของไม่เอาในใบปุ๋ย (E11-S11) · ไม่มีปุ่มลัด "หักเต็ม / ครึ่ง / ไม่หัก" · ไม่มีเตือนเมื่อหักเต็มจนคนกรีดได้เงินสด 0
ทาง 1/2/3 ถามทุกครั้งทุกคนที่หักหนี้ต้องผ่านการ์ดเลือก 3 วิธีรับเงิน (D-71) ทั้งที่เกือบทุกครั้งเลือกเหมือนครั้งก่อน · ข้อความยาว ("คนรับซื้อยางแยกเงินสดคืนหนี้ให้สวนอีกก้อน") ขึ้นสองบรรทัด
ปัดเศษ = ด่านบังคับกด "ถัดไป: ปัดเศษ" แล้ว sheet 3 ตัวเลือกขึ้นเอง (เมื่อมีเศษสตางค์) ต้องเลือกก่อนไปต่อ · ระหว่างนั้นทุกป้ายต้องเขียน "(ยังไม่ปัดเศษ)" ต่อท้ายจนยาว 2 บรรทัด
เทียบยอดเป็นอีกหน้า"เทียบยอด" ยาว 1.15 จอ ศัพท์บัญชี ("ตรวจ 3 ข้อ", "รวมจ่ายหนี้ = 0 เสมอ") ต้องกดผ่านทุกครั้งทั้งที่ถูกต้องอยู่แล้ว — เงินที่ต้องเป๊ะแต่เจ้าของไม่ต้องอ่านเมื่อผ่าน
หน้าจ่ายเงินซ้ำอีกรอบติ๊ก 4 ช่อง รวมช่อง "นัด ได้รับเงินสดแล้ว 0" ที่ไม่มีอะไรให้จ่าย · ปุ่ม "ปิดการขาย" เป็นปุ่มขอบ ดูเป็นปุ่มรอง
ผลรวมขายปกติ 2 คนมีหนี้ทั้งคู่: ~15 แตะ + เลื่อนอย่างน้อย 3 ครั้ง ผ่าน 4 จอ (ตรวจ · สรุป · เทียบยอด · จ่าย) + 2–3 sheet (หักหนี้ · ปัดเศษ · วิธีรับเงิน) ก่อนปิดการขาย

2 · อะไรไม่เปลี่ยน และอะไรเปลี่ยนกติกาเดิม

ไม่เปลี่ยน / เปลี่ยนรายละเอียด
สูตรเงิน (core)ไม่แตะ (ผลลัพธ์ทางเงินเท่าเดิม): ส่วนแบ่ง → หักหนี้ → ปัดเศษ → เงินสดที่ต้องจ่าย (D-60) · หักไม่เกินส่วนแบ่ง ไม่ติดลบ (D-18, FERT-6) · ยอดรวมทุกก้อน = ยอดขายถึงสตางค์ (D-72, NFR-3)
ข้อมูลที่บันทึกรูปแบบ event เดิมทั้งหมด (หักหนี้, หักกลบ, วิธีรับเงิน, ปัดเศษ, ติ๊กจ่าย) ไม่เพิ่ม ไม่เปลี่ยน — เปลี่ยนแค่จังหวะที่เขียน (ตอนกดยืนยัน) · `settle.ts`, `deduct.ts`, `debts.ts`, `buyer-check.ts` ใช้ตามเดิม
กติกาที่ตกลงไว้ และคงไว้ทั้ง 3 ทางรับเงินคืนหนี้ (D-71) · เฉพาะหนี้ที่ติดสวน (D-69) · หักกลบเจ้าของกดเอง (D-60) · ธง "หักเกินส่วนแบ่ง" และ Conflict ห้ามปิดการขาย (D-61, D-29)
เปลี่ยน — ต้องแก้ PRD/AC ถ้าเจ้าของเห็นด้วยD-85 (หนี้แยกจากยอดขายเป็นก้อน ก/ข/ค + ลูกศร ↘↗ สองสี): A รวมหนี้ไว้ในการ์ดคน เหลือลูกศร ↘ และสีน้ำเงินที่แถวหนี้ · D-72 (ต้องมีหน้าเทียบยอด + 3 ข้อตรวจ): ยุบเป็นแถบ + "ดูที่มา" · D-60 (ปุ่ม "หักเงินคืนหนี้" ต่อคน): เสนอไว้ก่อน บันทึกตอนยืนยัน · epic E05 (ปัดเศษถามทุกครั้ง): ใช้ค่าล่าสุด — เจ้าของต้องตัดสินใจ ยังไม่ได้ถาม D-85 ซ้ำ (รีวิวนักบัญชี/persona ของ D-85 ไม่ได้ทำกับแบบนี้)

4 · แนะนำ: แบบ A (การ์ดต่อคน) + ยืมจาก C มาใช้กับคนที่ไม่มีหนี้

  • ตรงกับสิ่งที่เจ้าของมาหา: "จ่ายเงินสดใครเท่าไหร่" เป็นตัวเลขใหญ่สุดของการ์ด · ส่วนแบ่ง → หักหนี้ เห็นสองบรรทัดใต้ตัวเลขนั้น ไม่ต้องไล่ ก/ข/ค
  • น่าจะเร็วที่สุด (ประมาณการ) โดยไม่ลดความเป๊ะ: แอปเสนอยอดหักให้ (ถูกอยู่แล้ว) กดยืนยันครั้งเดียว · ปัดเศษและเทียบยอดไม่ใช่ด่าน แต่เป็นลิงก์/แถบที่ทำงานเสมอ — ถ้าเงินไม่ตรง ปุ่มยืนยันกดไม่ได้
  • หักไม่เต็มก็ไม่ยาก: แถวหนี้แตะเดียว → ปุ่มลัด หักเต็ม/ครึ่ง/ไม่หัก หรือพิมพ์ด้วยแป้นเลขในแอป · ทั้ง 3 ทางรับเงิน (D-71) และหักกลบยังอยู่ แต่เป็นลิงก์รอง
  • ทำไมไม่ B: เพิ่มจอแต่ไม่ลดความคิด (เจ้าของต้องผ่านขั้นหักหนี้ทุกครั้งแม้ไม่มี) · ทำไมไม่ C ล้วน: เหมาะทีมใหญ่ แต่ซ่อนส่วนแบ่ง/หนี้ไว้หลังแตะ เจ้าของที่ตรวจเลขด้วยตาจะไม่เห็นที่มา — ใช้ C เฉพาะแถวย่อของคนไม่มีหนี้ และเมื่อมีคนเกิน 4 (CO-14)
