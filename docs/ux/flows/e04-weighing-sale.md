## 1. หลักที่ใช้ทุกหน้าใน E04

### 1.1 กฎพฤติกรรมภาคสนาม (design-system — พฤติกรรม ไม่ใช่ภาพ)

- หน้าชั่งใช้มือเดียว ยืน กลางแดด ใส่ถุงมือ: เป้าแตะตามกฎ design-system §8; พื้นที่กดค้างใหญ่ที่สุดในแอป
- ปุ่มทำลาย/ย้อนไม่ได้ (จบการขาย, ยกเลิกการขาย, ยกเลิกเข่ง) **ไม่วางติดพื้นที่กดค้างและไม่ติดกัน** + ยืนยันครั้งที่สอง (§8)
- **ไม่มีอะไรขวางการนับ**: เสียงเสีย, นาฬิกาผิด, ค้างส่ง, สงสัยนับซ้ำ, ตาชั่งไม่อ่านศูนย์ — แจ้งเท่านั้น (§7, F-7, F-17)
- ทุกสถานะมีคำ ไม่พึ่งสีอย่างเดียว (§7); การยืนยันการนับต้องเห็นได้แม้ไม่มีเสียง (F-17)
- สามระดับการสื่อสาร (§2, F-1): **สาธารณะ** = เลขเข่งเท่านั้น · **ผู้บันทึก** = ค่าอื่นทั้งหมด · **เสียง** = สิ่งที่อีกฝ่ายต้องรู้แต่อ่านไม่ได้
- โหมดผู้บันทึกเป็นแนวตั้งเสมอ; หมุนได้เฉพาะโหมดสาธารณะ (D-17)
- บันทึกลงเครื่องทันที ไม่มี "กำลังส่ง…" ขวาง; ไม่มีปุ่ม Sync (SYNC-1, D-3); ปิดแอป/ล็อกจอ/บังคับปิดแล้วเปิดใหม่ กลับมาที่การขายเดิม เลขเข่งเดิม (NFR-2)

### 1.2 ชุดสถานะกลาง

ใช้ชุดเดียวกับ E03 §1.4 (ว่าง, กำลังโหลด, ครั้งแรกหลังเข้ากลุ่ม, Pending Sync, บันทึกในเครื่องไม่สำเร็จ, error ถาวร + `ลองใหม่`,
Conflict + `[เลือกค่า]`, ข้อมูลไม่ถูกต้อง, รอข้อมูล) และคำไทยของ Conflict ตาม E03 Q21 — เพิ่มเฉพาะการชั่ง:

| สถานะ | เมื่อไร | ผู้ใช้เห็น | ขวางไหม |
|---|---|---|---|
| สถานะ sync **ต่อการขาย** (D-28) | ทุกการขาย | ในรายการการขายและหัวหน้าชั่ง: `ส่งแล้ว` / `ค้างส่ง` / `⟨ไอคอน Conflict⟩ ขัดกัน [ลองใหม่]` / `ส่งไม่สำเร็จ [ลองใหม่]` (ลำดับความสำคัญ + ปุ่มลองใหม่ตาม E01-S10 AC5; ภาพรวมของแอปเป็น `รอส่ง N` ตาม design-system §7 (คำตอบเจ้าของ 2026-10-03)) | ไม่ |
| เข่งขัดกัน (D-28) | เข่งที่อยู่ใน Conflict | ธง `ขัดกัน` ที่แถวเข่งในรายการเข่ง; ค่าที่ใช้ = ค่าก่อนแก้ (D-29) | ชั่งต่อได้; **จบการขายไม่ได้** (E01-S11) |
| ไม่มีเสียง | ปิดเสียง / TTS ไทยไม่พร้อม / เสียงล้ม | `ไม่มีเสียง` ที่แถบบน (§7) | ไม่ (S08 AC3) |
| เวลาผิด | `clock_anomaly` | `เวลาผิด` ที่แถบบน (§7) | ไม่ (NFR-3) |
| ส่งต่อแล้ว (ล็อก) | เครื่องนี้กด "ส่งต่อ" | หน้าชั่งเป็นแบบอ่านอย่างเดียว + `ส่งต่อแล้ว — เข่ง ⟨N⟩ เป็นต้นไปบันทึกที่เครื่องอื่น` (ชื่อเครื่องที่รับรู้ได้หลัง sync/QR เท่านั้น — §14.3) | **ขวางการบันทึกบนเครื่องนี้** (S12 AC5) |
| สงสัยนับซ้ำ | ตรวจพบหลังรวมข้อมูล (S14) | ธง `สงสัยนับซ้ำ N คู่` ที่การขาย + แถวเข่ง | ไม่ขวางการชั่ง (S14 AC5); จบการขาย → Q15 |
| บันทึกย้อนหลัง | เข่งจาก S10 | ป้าย `บันทึกย้อนหลัง` ทุกที่ที่เข่งแสดง | ไม่ |
| ยังไม่ใส่ราคา | ไม่มี `price_set` | `ยังไม่ใส่ราคา` ที่หัวการขาย | ชั่งได้ (D-11); จบการขายไม่ได้ (S11 คำตอบเจ้าของ) |

## 3. E04-S01 โมเดลการขายและเลขเข่งต่อเนื่อง

Story นี้เป็น core อย่างเดียว ("ยังไม่แตะ UI") — **ไม่มีหน้าจอของตัวเอง** ผลต่อ UX ที่หน้าจออื่นต้องสะท้อน:

- เลขเข่งต่อเนื่องทั้งการขาย ข้ามจุดและสวน (SALE-10): ทุกหน้าที่แสดงเลขเข่งใช้เลขนี้ ไม่มี "เข่งที่ N ของจุดนี้"
- เมื่อสลับจุด ตัวเลขบนจอสาธารณะ **ไม่กลับไป 1** — แก้ปัญหา F-4 (ตัวเลขตกจาก 87 → 1) โดยโครงสร้าง
- ยอดต่อจุด / คนกรีด / สวน / การขาย แสดงที่สรุปการขาย (§13) และแท็บรายการเข่ง (§11)
- เข่งของแดงกับนัดไม่ปนกัน (SALE-4): ทุกแถวเข่งบอกจุดชั่ง → คนกรีด
- การขายเก่าในเครื่องถูกทิ้ง (คำตอบเจ้าของ) — ไม่มีหน้าจอย้ายข้อมูล

## 4. E04-S02 เริ่มการขายและหัวการขาย

### 4.1 Flow — เริ่ม (เป้า ≤ 4 แตะถึงเข่งแรก เมื่อใช้ค่าเริ่มต้น — S02 AC5)
1. รายการการขาย ▸ `[+ การขายใหม่]` (แตะ 1)
2. **เลือกสวน** (แตะ 2) — ถ้ากลุ่มมีสวนยางสวนเดียว ข้ามขั้นนี้ และนับแตะลดลงหนึ่ง
3. **เลือกจุดชั่ง** — รายการจุดของสวนนั้น จัดกลุ่มตามคนกรีด ณ วันนี้ (ขั้น "โซน/คนกรีด" ของ SALE-1 รวมเป็นหัวกลุ่ม — Q2) (แตะ 3)
   - จุดที่ไม่มีคนกรีด ณ วันขาย → คำเตือนไม่ขวาง (E03 §6.5)
4. ด่านตรวจศูนย์/ตะกร้า ตามโหมด (§5) — แตะในด่านนับรวมหรือไม่ → Q3
5. หน้าชั่ง → กดค้าง = เข่งแรก (แตะ 4)
- หัวการขาย **เติมให้ทั้งหมด** และไม่ถามระหว่างทาง: วันที่ = วันนี้, ผู้ซื้อ = รายล่าสุด, ผู้จัดการสวน = จากข้อมูลหลัก (SALE-2)
  แก้ได้ทีหลังจากเมนู ⋯ ▸ หัวการขาย
- ไม่มีผู้ซื้อในกลุ่มเลย → ขั้นเพิ่ม `ผู้ซื้อ` ก่อนเลือกสวน: `ยังไม่มีผู้ซื้อ — ใส่ชื่อผู้ซื้อ` (PeoplePicker แบบผู้ซื้อ, E03 §2.6) หรือ `[ข้ามไปก่อน]` (Q4)

### 4.2 หน้าจอ — เลือกสวน / เลือกจุดชั่ง
```
‹ ยกเลิก                  การขายใหม่ · เลือกสวน
สวนจันทเขลม                                   ▸
สวนฝั่งคลองพลู                                 ▸
```
```
‹ สวน                     ⟨ชื่อสวน⟩ · เลือกจุดชั่ง
แดง
  ⟨จุด⟩   ชั่งแล้วในการขายนี้ ⟨N⟩ เข่ง              ▸
  ⟨จุด⟩                                        ▸
นัด
  ⟨จุด⟩                                        ▸
ยังไม่มีคนกรีด
  ⟨จุด⟩   ⟨ไอคอนเตือน⟩ ยังไม่มีคนกรีด ณ วันที่ขาย     ▸
```
- ว่าง (สวนไม่มีจุดชั่ง): `สวนนี้ยังไม่มีจุดชั่ง — เพิ่มได้ที่ตั้งค่า ▸ สวนและจุดชั่ง` `[ไปเพิ่มจุดชั่ง]`
- ว่าง (ไม่มีสวน): `ยังไม่มีสวน — สร้างโครงสร้างตั้งต้นก่อน` `[ไปตั้งค่าสวน]` (E03 §4.3)
- ไม่มีโซนก็ไม่แสดงอะไรเกี่ยวกับโซน (MD-2); มีโซน → แสดงชื่อโซนเป็นข้อมูลรองต่อแถว ไม่ใช่ขั้นแยก (Q2)

### 4.3 หัวการขาย (เมนู ⋯ ▸ หัวการขาย)
```
‹ กลับไปชั่ง               หัวการขาย
วันที่*        ⟨วันนี้⟩
ผู้ซื้อ         ⟨รายล่าสุด⟩ [เปลี่ยน ▸]
ผู้จัดการสวน    ⟨จากข้อมูลหลัก⟩ [เปลี่ยน ▸]
เวลาเริ่มชั่ง    ไม่ได้บันทึก [ใส่เวลา]
หมายเหตุ       ____
รูป/เอกสาร     ▸ (§12.2)
ราคา (฿/กก.)   ยังไม่ใส่ [ใส่ราคา] (§4.4)
ขนาดเข่งของการขายนี้   ⟨ค่าเริ่มต้นกลุ่ม⟩ [เปลี่ยน ▾]   ← S03 AC5 (รายการขาย); รายจุดเปลี่ยนในด่าน §5
```
- ไม่มีฟิลด์หัวหน้าคนงาน ไม่มีตัวเลือก "ขายที่ลานล้ง" (D-10)
- แก้ฟิลด์ → บันทึกทันทีเมื่อออกจากช่อง (เหมือน S6 autosave เดิม) + `บันทึกแล้ว`
- ผู้จัดการสวนไม่มีในข้อมูลหลัก → `ไม่ได้บันทึก` (ไม่แต่ง)

### 4.4 ราคา (ใส่เมื่อไหร่ก็ได้ก่อนจบการขาย — D-11)
```
ราคา (บาท/กก.)*   ____        ← ไม่มีค่าเติมจากการขายก่อน (SALE-3)
[บันทึกราคา]
```
- ตรวจ: ไม่ใช่ตัวเลข / ≤ 0 → `ใส่ราคาเป็นตัวเลขมากกว่า 0`; ทศนิยมเกิน 2 ตำแหน่ง → `ใส่ราคาได้ถึงทศนิยม 2 ตำแหน่ง`
- ไม่มี %DRC ไม่มีโหมดราคาอื่น (D-11)
- ราคาแก้ซ้อนสองเครื่อง → Conflict (เงิน) ตามชุดสถานะกลาง; แก้ราคาหลัง Completed → §13.4

## 5. E04-S03 ด่านตรวจศูนย์/ตะกร้า และขนาดเข่ง

### 5.1 เมื่อไรถาม (โหมดจาก E03-S07)
- `ทุกจุดชั่ง` (ค่าเริ่มต้น): ก่อนเข่งแรกของทุกจุด
- `เฉพาะจุดแรกของแต่ละสวน`: จุดแรกที่ชั่งในแต่ละสวนของการขายนี้
- `ข้ามทั้งหมด`: ไม่ถาม; บันทึก `ข้ามการตรวจ` ในการขาย และแสดงในสรุปการขาย `ข้ามการตรวจศูนย์/ตะกร้า (ตามตั้งค่า)`

### 5.2 Flow ด่าน (คง 3 ขั้นจาก S9 — ศูนย์ → ตะกร้า → อ่านทวน)
1. **ศูนย์**: `ตาชั่งอ่าน 0 ไหม` `[อ่าน 0]` `[ไม่ใช่ 0]`
   - `[ไม่ใช่ 0]` → ติดธง `ตาชั่งไม่อ่านศูนย์` ที่จุดนี้แล้ว **ไปต่อ** (S03 AC4) — ไม่มีขั้นแก้
2. **ตะกร้า**: `วางตะกร้าเปล่า — ตาชั่งอ่านเท่าไร` ช่อง `⟨ค่าตะกร้าเริ่มต้น⟩ กก.` (แก้ได้) `[ยืนยันตะกร้า]`
3. **อ่านทวน + ขนาดเข่ง**:
```
⟨จุด⟩ · แดง
เข่งเต็ม: ยางสุทธิ ⟨50⟩ กก. [เปลี่ยน ▾]
ตะกร้า: ⟨2⟩ กก.
ตาชั่งควรอ่าน: ⟨52⟩ กก.          ← SALE-7
[พร้อมชั่ง]
```
4. `[พร้อมชั่ง]` → หน้าชั่ง + เสียงอ่านทวน (ถ้าเจ้าของต้องการ — Q7)
- `[เปลี่ยน ▾]` ขนาดเข่ง: เลือกจากค่าตั้งต้นกลุ่ม (E03-S07) ใช้กับ **จุดนี้ในการขายนี้** (S03 AC5)
- ไม่มีค่าตะกร้าตั้งต้นในกลุ่ม (E03 §8.1) → ช่องว่าง บังคับใส่: `ใส่น้ำหนักตะกร้าที่ตาชั่งอ่าน`
- ตรวจ: ค่าตะกร้าไม่ใช่ตัวเลข / < 0 → `ใส่น้ำหนักตะกร้าเป็นตัวเลข` (ทศนิยมตาม E03 Q19)
- ความคืบหน้าในด่านรอด reload (คงจาก S9 e2e)
- ด่านอยู่ **บนพื้นที่กดค้าง** แทนตัวนับ — กดค้างในด่านไม่นับ (คง S9)

## 6. E04-S04 กดค้างเพื่อนับ + แก้บั๊กแตะหลายนิ้ว

1. กดค้างบนพื้นที่ชั่ง → ขอบวิ่งรอบพื้นที่ตามเวลา (E03-S07 ค่าเครื่องนี้ ค่าเริ่มต้น 0.7 วินาที) — ภาพของ "bezel sweep" ตาม design-system §5

   (การสั่นยังไม่อยู่ใน dependency ที่อนุมัติ — architecture §Open ข้อ 3)
   - บันทึกลงเครื่องไม่สำเร็จ → **ไม่มีการยืนยัน ไม่มีเสียง** ตัวเลขไม่เปลี่ยน + `บันทึกไม่สำเร็จ — เข่งนี้ยังไม่นับ ลองกดค้างอีกครั้ง`

- เปิดการขาย Draft ที่เครื่องอื่นก็กำลังชั่งแบบไม่ส่งต่อ (โหมดอิสระ SYNC-6): เปิดได้ตามปกติ ไม่มีข้อความพิเศษ — เข่งที่ชนกันจัดการที่ §16
- การขาย Completed: หน้าชั่งบันทึกเข่งใหม่ได้ไหม → Q23
- แท็บอื่นแสดงตัวเลขเล็กของเข่งปัจจุบันที่แถบบนตลอด (F-19)
- สลับจุด/สวน ≤ 2 แตะ: `[สลับจุด ▾]` (1) → เลือกจุด (2) — มีรายการสวนอื่นอยู่ท้ายรายการเดียวกัน
- ยังไม่ผ่านด่าน: พื้นที่กดค้างแสดงด่าน (§5) แทนตัวเลข

### 7.2 สถานะ

## 8. E04-S06 เข่งไม่เต็ม และเข่งเชื่อม

### 8.1 Flow — บันทึกเข่งไม่เต็ม
1. `[เข่งไม่เต็ม]` → แผงใต้ตัวเลข **ไม่บังตัวเลข** (F-13)
```
เข่ง ⟨12⟩ ไม่เต็ม — ⟨จุด⟩ · แดง
ตาชั่งอ่าน (กก.)*   ____   [−] [+]
ยางสุทธิ = ⟨22⟩ − ⟨2⟩ = ⟨20⟩ กก.        ← คำนวณทันทีที่พิมพ์ (SALE-9)
[บันทึก]                         [ยกเลิก]
```
2. ตรวจ: ไม่ใช่ตัวเลข → `ใส่ค่าที่ตาชั่งอ่าน`; ≤ ตะกร้า → `ค่าที่อ่านต้องมากกว่าน้ำหนักตะกร้า (⟨2⟩ กก.)`;
   ≥ ค่าที่ตาชั่งควรอ่านของเข่งเต็ม → `ค่านี้เท่าเข่งเต็มหรือมากกว่า — ใช้กดค้างแทน หรือตรวจตาชั่ง` (ไม่บันทึก — Q9)
3. `[บันทึก]` → เข่ง 12 **เปิดค้าง** (SALE-11) + แถว `เข่งไม่เต็มที่เปิดอยู่: เข่ง 12 — 20 กก.` + เสียง (§9)
4. แสดงปุ่ม `[จบเข่งแล้ว / เป็นเศษ]` ใต้แถวเข่งเปิด (ห่างพื้นที่กดค้าง)
- `[−] [+]` ปรับทีละ 0.5 กก. + พิมพ์ตรงได้ (F-22)

### 8.2 Flow — สลับจุดขณะมีเข่งไม่เต็มเปิดอยู่
1. `[สลับจุด ▾]` → เลือกจุด
2. ตัดสิน:
   - จุดของ **คนกรีดคนเดิม** → ถาม (SALE-11):
```
เข่ง ⟨12⟩ ยังไม่เต็ม (⟨20⟩ กก. จาก ⟨จุดเดิม⟩)
[เติมเข่ง 12 ต่อ]          [เริ่มเข่งใหม่]
เริ่มเข่งใหม่ = เข่ง 12 ปิดเป็นเศษ
```
   - จุดของ **คนกรีดคนอื่น** หรือไม่มีคนกรีด → ไม่ถาม: เข่ง 12 ปิดเป็นเศษก่อน + ข้อความ `เข่ง 12 ปิดเป็นเศษ (⟨20⟩ กก.) — ยางคนละคนกรีดเติมรวมกันไม่ได้` + เสียง "สิบสอง เศษ" (SALE-12)
3. ด่านของจุดใหม่ (ถ้าโหมดกำหนด) → หน้าชั่ง
4. `[เติมเข่ง 12 ต่อ]` → เข่งปัจจุบันยังเป็น 12; ส่วนถัดไปบันทึกด้วย `[เข่งไม่เต็ม]` ที่จุดใหม่ (ค่าตาชั่งอ่านของส่วนนี้)
   - ส่วนรวมกันถึงน้ำหนักเข่งเต็ม → **ปิดเป็นเข่งเต็มอัตโนมัติ** ยังแสดง `(20 + 30)` (คำตอบเจ้าของ) → เลขถัดไปพร้อม
   - สองจุดใช้ขนาดเข่งต่างกัน ใช้ขนาดไหนเป็นเกณฑ์ → Q25
   - เกินน้ำหนักเข่งเต็ม → Q10
5. แสดงเข่งเชื่อม: `เข่ง 12 — (20 + 30) กก. = 50 กก.`; ยอดของแต่ละจุดนับเฉพาะส่วนของตัวเอง (SALE-11)

### 8.3 Flow — จบเข่งแล้ว / เป็นเศษ
`[จบเข่งแล้ว / เป็นเศษ]` → ปิดทันที → `เข่ง 12 เป็นเศษ (⟨20⟩ กก.)` + เสียง "สิบสอง เศษ" → ไม่เสนอเติมต่ออีก, เลขถัดไป 13 (SALE-13)
- กดปิดเป็นเศษผิด แก้อย่างไร (`[ย้อนกลับเข่งล่าสุด]` ลบทั้งเข่ง — §11.1) → Q24

- **เข่งเชื่อม** (S09 AC2/AC3 "เข่งหรือส่วนเข่ง"): หน้าเข่งแสดงทีละส่วน
```

- เปลี่ยนจุด: เลือกจุดใหม่ → ถ้าคนละคนกรีด `ย้ายเข่งนี้ไปเป็นของ ⟨นัด⟩ — ยอดของแดงและนัดจะเปลี่ยน` `[ย้าย]` `[ไม่]`

- การขาย Completed: การแก้ที่เปลี่ยนเงินขอเหตุผล (§13.4)
- สองเครื่องแก้เข่งเดียวกัน → Conflict ธงที่เข่ง + การขาย (§1.2)

## 12. E04-S10 บันทึกย้อนหลังแบบรวม และไฟล์แนบ

## 13. E04-S11 สถานะการขาย และการแก้หลัง Completed

### 13.1 แท็บสรุป
```
การขาย ⟨วันที่⟩ · ผู้ซื้อ ⟨ชื่อ⟩ · ⟨สถานะการขาย — คำตาม Q19⟩
ราคา  ⟨ยังไม่ใส่⟩ [ใส่ราคา]
ต่อคนกรีด    แดง ⟨N⟩ เข่ง ⟨กก.⟩ · นัด ⟨N⟩ เข่ง ⟨กก.⟩
ต่อจุดชั่ง    ⟨จุด⟩ ⟨N⟩ เข่ง ⟨กก.⟩ ▸ …
ต่อสวน       ⟨สวน⟩ ⟨กก.⟩ …
รวม          ⟨N⟩ เข่ง ⟨กก.⟩
สิ่งที่ต้องจัดการก่อนจบ:
  ⟨ไอคอน Conflict⟩ ขัดกัน 1 รายการ ▸   · สงสัยนับซ้ำ 2 คู่ ▸ (Q15) · ยังไม่ใส่ราคา ▸
[จบการขาย]
—
[ยกเลิกการขาย]            ← เฉพาะการขาย Draft (S11 AC1)
… (ส่วนแนบ / ข้อมูลอื่น) …
[ลบการขาย]               ← ท้ายหน้า แยกห่างจากยกเลิก (design-system §8)
```
- ยอดสรุปเงิน/ส่วนแบ่งอยู่ E05 — แท็บนี้แสดงน้ำหนักเท่านั้น

### 13.2 Flow — จบการขาย (Draft → Completed)
1. `[จบการขาย]` → ตรวจ (ตามลำดับ):
   - ยังไม่ใส่ราคา → `ใส่ราคาก่อนจบการขาย` + เปิดช่องราคา (คำตอบเจ้าของ S11)
   - มี Conflict ค้าง → `ยังมีข้อมูลขัดกัน — เลือกค่าก่อนจบการขาย` `[ไปเลือก]` (E01-S11)
   - มีเข่งไม่เต็มเปิดอยู่ → `เข่ง ⟨N⟩ ยังเปิดอยู่ — จบการขายจะปิดเป็นเศษ` (ข้อเสนอ)
   - สงสัยนับซ้ำค้าง → Q15
2. ยืนยัน: `จบการขาย ⟨วันที่⟩ — ⟨N⟩ เข่ง ⟨กก.⟩ ราคา ⟨฿/กก.⟩` `[จบการขาย]` `[ยังไม่จบ]`
3. Completed → ไป E05 สรุปเงิน (ไม่อยู่ในเอกสารนี้)
- มีเครื่องอื่นยังไม่ได้ส่งข้อมูลเข้ามา → แนะนำ QR รวมข้อมูลก่อน (§15) — `ถ้ามีเครื่องอื่นชั่งการขายนี้แบบไม่มีเน็ต ให้รวมข้อมูลด้วย QR ก่อนจบ` (ไม่ขวาง)

### 13.3 ยกเลิก / ลบ
- `[ยกเลิกการขาย]` (Cancelled — ผลทางธุรกิจ): `ยกเลิกการขายนี้ไหม — เข่งยังเก็บไว้แต่ไม่นับในยอดใด ๆ` เหตุผล → Q18 `[ยกเลิกการขาย]` `[ไม่]`
- `[ลบการขาย]` (Soft Delete — E01-S04): `ลบการขายนี้ไหม — กู้คืนได้ที่ "ที่ลบแล้ว"` — แยกห่างและต่างคำจากยกเลิก (SYNC-10 ≠ Cancelled)
- รายการการขาย: Cancelled ยังแสดง + ป้าย `ยกเลิกแล้ว`; ลบแล้วไม่แสดง
- เครื่องหนึ่ง Completed อีกเครื่อง Cancelled → Conflict สถานะ ตามชุดกลาง

### 13.4 แก้การขายที่ Completed (ไม่ต้องเปิดใหม่ — D-16)
- แก้ตรงได้ทุกหน้า; ถ้าการแก้เปลี่ยนเงิน (น้ำหนักเข่ง, ราคา, เข่ง/ยกเลิกเข่ง, ย้ายจุดต่างคนกรีด) → ก่อนบันทึก:
```
การแก้นี้เปลี่ยนยอดเงิน — เหตุผล*
( ) ชั่งผิด  ( ) ราคาผิด  ( ) ผู้ซื้อแจ้งยอดต่าง  ( ) อื่น ๆ ____
สถานะการจ่ายของ ⟨แดง⟩ จะถูกติดธง "ต้องตรวจ"
[บันทึก]                 [ยกเลิก]
```
  (รายการเหตุผล = คำตอบเจ้าของ S11)
- ไม่เปลี่ยนเงิน (หมายเหตุ, รูป, เวลาเริ่ม) → บันทึกเลยไม่ถาม (S11 AC4)
- เข่งจากเครื่องที่ออฟไลน์มาถึงหลัง Completed → ธง `ต้องตรวจ` ที่การจ่าย (architecture §ตรวจ Conflict) + ข้อความในรายการการขาย `มีข้อมูลมาเพิ่มหลังจบการขาย`

### 13.5 รายการการขาย
```

## 14. E04-S12 ส่งต่อ / รับช่วง

### 14.1 Flow — เครื่องเดิม "ส่งต่อ" (≤ 2 แตะ)
1. หน้าชั่ง ▸ `[ส่งต่อ]` (แตะ 1)
```
ส่งต่อการขายให้เครื่องอื่น
เครื่องที่รับจะต่อจาก เข่ง ⟨13⟩
⟨QR ของการขาย⟩            ← ให้เครื่องรับสแกน (คำตอบเจ้าของ: QR หรือพิมพ์เลข)
เข่งล่าสุดที่บันทึก: ⟨12⟩
[ยืนยันส่งต่อ]              (แตะ 2)
```

- มีเข่งไม่เต็มเปิดอยู่ → Q20

### 14.2 Flow — เครื่องรับ "รับช่วง" (≤ 2 แตะ)
1. รายการการขาย ▸ `[รับช่วงการขาย]` (แตะ 1) → กล้องสแกน QR
2. สแกนได้ → ยืนยัน:
```
รับช่วงการขาย ⟨วันที่⟩ · ⟨ผู้ซื้อ⟩
ต่อจาก เข่ง ⟨13⟩ (ล่าสุด ⟨12⟩)
[รับช่วงการขาย]               (แตะ 2)
```
3. → หน้าชั่งของการขายนั้น เข่งปัจจุบัน 13 (S12 AC2/AC3)
- **เครื่องเดิมใช้ไม่ได้ (แบตหมด)** (ทางสำรอง — ไม่อยู่ในเกณฑ์ ≤ 2 แตะ) → `[สแกนไม่ได้ — ใส่เลขเอง]`: เลือกการขาย (ถ้าเครื่องนี้เคยเห็น) และพิมพ์ `เข่งล่าสุดที่เห็นบนจอเครื่องเดิม ____`
  → ยืนยัน `ต่อจากเข่ง ⟨N+1⟩` (คำตอบเจ้าของ S12) — ถ้าเครื่องนี้ไม่เคยเห็นการขายนี้ → Q21 (architecture)
- ไม่ได้สิทธิ์กล้อง: `แอปยังไม่ได้รับอนุญาตให้ใช้กล้อง — ใส่เลขเองได้` `[ใส่เลขเอง]`
- QR ไม่ใช่ของกลุ่มนี้/อ่านไม่ได้: `QR นี้ไม่ใช่การขายของกลุ่มนี้` / `อ่าน QR ไม่ได้ — ลองอีกครั้ง หรือใส่เลขเอง`

### 14.3 เครื่องที่ส่งต่อแล้ว
- หน้าชั่งอ่านอย่างเดียว:
```

⟨หลัง sync หรือ QR: รับช่วงโดย ⟨ชื่อผู้ใช้ · เครื่อง⟩⟩
บันทึกเข่งบนเครื่องนี้ไม่ได้
[รับช่วงกลับ]
```
- กดค้างบนพื้นที่ชั่ง → ไม่นับ + `เครื่องนี้ส่งต่อแล้ว — รับช่วงกลับก่อนชั่ง` (S12 AC5)
- `[รับช่วงกลับ]` ใช้กติกาเดียวกับรับช่วง (สแกน/ใส่เลขจากเครื่องที่ถืออยู่ — S12 §Offline)
- ชื่อผู้รับ: QR ทางเดียวทำให้เครื่องเดิมไม่รู้ว่าใครรับ จนกว่าจะ sync/QR รวมข้อมูล → แสดงชื่อเมื่อรู้เท่านั้น (Q31)
- **เครื่องเดิมกลับมาใช้ได้หลังอีกเครื่อง "ใส่เลขเอง" รับช่วงไปแล้ว**: เครื่องเดิมไม่ได้กดส่งต่อจึง **ไม่ล็อก** และไม่รู้จนกว่าจะ sync/QR —
  ถ้าบันทึกต่อ เลขจะชนกับอีกเครื่อง → ตรวจนับซ้ำ §16 จับได้; เมื่อเห็นการรับช่วงแล้ว แสดง `เครื่องอื่นรับช่วงการขายนี้ไปแล้วตั้งแต่เข่ง ⟨N⟩` + `[รับช่วงกลับ]` (ข้อเสนอ)

## 15. E04-S13 รวมข้อมูลด้วย QR ตอนปิดการขาย

### 15.1 Flow
1. ทั้งสองเครื่องเปิด สรุปการขาย ▸ `รวมข้อมูลด้วย QR`
2. รวม **สองทาง ทีละรอบ** — รอบแรกเครื่อง A แสดง B สแกน แล้วสลับ (ยอดต้องตรงกันทั้งสองเครื่อง — S13 AC4) ลำดับ → Q22
3. เครื่องแสดง:
```
รวมข้อมูล · ภาพ ⟨2⟩/⟨3⟩
⟨QR⟩
ให้อีกเครื่องสแกนทีละภาพ — เมื่ออีกเครื่องขึ้น "สแกนแล้ว ⟨2⟩/⟨3⟩" กด [ภาพถัดไป] (เครื่องที่แสดงไม่รู้เองว่าสแกนแล้ว)
```
4. เครื่องสแกน: `สแกนแล้ว ⟨2⟩/⟨3⟩` → ครบ → `รวมแล้ว — เพิ่ม ⟨N⟩ เข่ง` → ตรวจนับซ้ำอัตโนมัติ (S13 AC5 → §16)
5. ทั้งสองเครื่องแสดงยอด `⟨N⟩ เข่ง ⟨กก.⟩` ให้เทียบด้วยตา (S13 AC4)
- สแกนซ้ำ → `ภาพนี้รับแล้ว` ไม่เพิ่มเข่งซ้ำ (S13 AC2)
- ไม่มีข้อมูลต่างกัน → `ข้อมูลตรงกันแล้ว ไม่ต้องรวม`
- สแกนค้างกลางทาง → ภาพที่รับแล้วเก็บไว้ สแกนต่อได้: `รับแล้ว ⟨1⟩/⟨3⟩ — สแกนภาพที่เหลือ`
- ไม่ได้สิทธิ์กล้อง → ใช้อีกเครื่องเป็นผู้สแกน: `เครื่องนี้สแกนไม่ได้ — ให้อีกเครื่องสแกนแทน`

## 16. E04-S14 ตรวจนับซ้ำ + ไทม์ไลน์รายเครื่อง

### 16.1 เมื่อพบ (หลัง sync หรือ QR)
- ไม่ขัดจังหวะการชั่ง: ธงที่การขาย `สงสัยนับซ้ำ ⟨N⟩ คู่` + แถวเข่ง (S14 AC5); ไม่มี popup กลางการกดค้าง
- ตรวจได้จากสรุปการขาย ▸ `สงสัยนับซ้ำ ▸`

### 16.2 หน้าจอ — ตัดสินทีละคู่
```
‹ สรุป                    นี่คือการนับซ้ำไหม? (คู่ ⟨1⟩/⟨2⟩)
เครื่อง ⟨A⟩: เข่ง ⟨14⟩ · ⟨จุด⟩ · ⟨50⟩ กก. · ⟨10:02:13⟩
เครื่อง ⟨B⟩: เข่ง ⟨14⟩ · ⟨จุด⟩ · ⟨50⟩ กก. · ⟨10:02:18⟩
ห่างกัน ⟨5⟩ วินาที / เลขเข่งชนกัน
ไทม์ไลน์
  เครื่อง A  ──●──●──●───────●──
  เครื่อง B  ─────────●──●──●──     ← ช่วงที่บันทึกทับกันเน้นด้วยคำ "ทับกัน"
[ใช่ ซ้ำ — ยกเลิกเข่งของเครื่อง A]
[ใช่ ซ้ำ — ยกเลิกเข่งของเครื่อง B]
[ไม่ซ้ำ — เก็บทั้งคู่]
```
- "ใช่ ซ้ำ" → ยกเลิกเข่งที่เลือก (S09 — ขีดฆ่า เลขอื่นไม่เปลี่ยน); "ไม่ซ้ำ" → เก็บทั้งคู่ บันทึกการตัดสิน (S14 AC4)
- "ไม่ซ้ำ" แต่เลขเข่งเหมือนกัน → สองเข่งเลขเดียวกันแสดงอย่างไร → Q32
- นาฬิกาเครื่องคลาดจนเทียบเวลาไม่ได้ → แสดง **ทุกคู่ที่เลขเข่งชน** (คำตอบเจ้าของ) และแทน "ห่างกัน" ด้วย `เวลาของเครื่อง ⟨B⟩ เชื่อไม่ได้ — ดูจากเลขเข่ง`
- ไทม์ไลน์เป็นแบบข้อความ/แถว ไม่ใช่กราฟละเอียด (SYNC-7 "แบบง่าย") — ภาพจริงตัดสินตอนทำ UI
- ตัดสินได้ออฟไลน์; การตัดสินเป็น event ที่ sync; สองเครื่องตัดสินคู่เดียวกันต่างกัน → Conflict (ชุดกลาง)
- ว่าง: `ไม่พบการนับซ้ำ`
