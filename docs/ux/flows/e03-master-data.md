- `[ปุ่ม]` = ปุ่ม · `( ) / (•)` = เลือกได้ข้อเดียว · `[ ] / [x]` = เลือกได้หลายข้อ · `▸` = แตะแล้วไปหน้าถัดไป ·
  `____` = ช่องกรอก · `*` = บังคับ · `⟨…⟩` = ค่าที่แอปเติม
- ลำดับในโครงหน้าจอ = ลำดับจากบนลงล่าง ไม่ได้กำหนดขนาดหรือหน้าตา

## 1. หลักที่ใช้ทุกหน้าใน E03

### 1.1 กฎพฤติกรรมภาคสนาม (จาก design-system — ไม่ใช่การออกแบบภาพ)

- เป้าแตะ ≥ 48 (ใช้ซ้ำบ่อย 56) — §8, §12.10 ข้อ 6
- ปุ่มทำลาย/ย้อนไม่ได้ (เก็บถาวร เลิกใช้โซน แยก/รวมโซน) ไม่วางติดกัน และต้องยืนยันครั้งที่สองเสมอ — §8
- สถานะไม่พึ่งสีอย่างเดียว: มีคำเสมอ — §7, NFR-4
- ข้อความขยายตามขนาดตัวอักษร S/M/L (E03-S08); ที่ขนาด L ปุ่มหลักต้องไม่หลุดจอแนวตั้ง
- พิมพ์ให้น้อยที่สุด: ค่าเริ่มต้นเติมให้ (วันที่ = วันนี้), เลือกจากรายการแทนพิมพ์ (หลักการหลักข้อ 1)
- ห้ามแต่งข้อมูลที่ขาด: ฟิลด์ไม่บังคับที่ว่างแสดงป้ายของ E01-S15 — `ไม่ได้บันทึก` = ยังไม่มีใครใส่ (ค่าเริ่มต้นของช่องว่าง),
  `ไม่ทราบ` = ผู้ใช้เลือกบอกว่าไม่มีใครรู้ (เช่น ติ๊ก `ไม่ทราบ` ที่ปีที่ปลูก), `ประมาณ` = ผู้ใช้ติ๊กว่าเป็นค่าประมาณ
  ยกเว้น GPS ที่ MD-1 กำหนดให้ว่าง = `ไม่ทราบ`
- บันทึกทันทีในเครื่อง ไม่มีขั้น "กำลังส่ง…" ขวางผู้ใช้ (SYNC-1); ไม่มีปุ่ม Sync (D-3)

เหตุผล: เจ้าของตอบ E03-S07 ว่าเวลากดค้าง + เสียงเป็นของเครื่อง ที่เหลือเป็นของกลุ่ม — ผู้ใช้ต้องรู้ว่าเปลี่ยนแล้ว
กระทบเครื่องอื่นหรือไม่ จึงแยกสองกลุ่มด้วยหัวข้อและคำอธิบาย ไม่ปนกัน

### 1.3 รูปแบบกลาง: รายการ → รายละเอียด → ฟอร์ม (ใช้กับ คน, ผู้ซื้อ, สวน, จุดชั่ง, โซน)

**หน้ารายการ**
```
‹ กลับ              ⟨หัวข้อ เช่น "คน"⟩          ⟨ตัวบอกสถานะ sync ภาพรวม — E01-S10⟩
[ตัวกรอง (ถ้ามี)]
⟨แถว⟩ ชื่อ · ข้อมูลรอง · ⟨ธงต่อแถว: "ขัดกัน" เสมอ; "ค้างส่ง" ขึ้นกับ Q20⟩   ▸
…
[+ เพิ่ม⟨สิ่งนั้น⟩]
ที่เก็บถาวร (N) ▸          ← แสดงเมื่อ N > 0
```

**หน้าฟอร์ม** (สร้างและแก้ใช้หน้าเดียวกัน)
```
‹ ยกเลิก            ⟨"เพิ่ม…" / "แก้…"⟩
⟨ฟิลด์ตามลำดับความสำคัญ⟩
⟨ข้อความผิดใต้ฟิลด์ที่ผิด⟩
[บันทึก]
```
- กด `บันทึก` → เก็บในเครื่องทันที → กลับหน้าก่อนหน้า + ข้อความสั้น `บันทึกแล้ว`
- ออกจากฟอร์มที่แก้ไว้แต่ยังไม่บันทึก → ถาม `ยังไม่ได้บันทึก — ออกโดยไม่บันทึกไหม` `[ออก]` `[อยู่ต่อ]`

**เก็บถาวร** (ทุก entity ใน E03) — กลไกเดียวกับ Soft Delete ของ E01-S04 (D-27, S01 "เก็บถาวรแทนลบ"); คำที่ใช้รอ Q3
```
เก็บถาวร "⟨ชื่อ⟩" ไหม
จะไม่ขึ้นในตัวเลือกอีก บันทึกเก่าที่อ้างถึงยังแสดงชื่อนี้
กู้คืนได้ที่ "ที่เก็บถาวร"
[เก็บถาวร]                     [ยกเลิก]
```
- หน้า `ที่เก็บถาวร`: รายการเดียวกัน + ปุ่ม `[กู้คืน]` ต่อแถว → กู้คืนแล้ว `กู้คืนแล้ว`
- บันทึกเก่าแสดงชื่อที่เก็บถาวรต่อท้ายด้วย `(เก็บถาวร)` เพื่อไม่ให้ดูเหมือนยังใช้อยู่

### 1.4 ชุดสถานะกลาง (ทุกหน้าใน E03 ใช้ชุดนี้ เว้นแต่ระบุในหัวข้อ story)

| สถานะ | เมื่อไร | สิ่งที่ผู้ใช้เห็น (ข้อความ) | ทำอะไรได้ |
|---|---|---|---|
| ว่าง | ยังไม่มีรายการ | ข้อความอธิบาย + ปุ่มเพิ่ม (ข้อความเฉพาะ story) | เพิ่มได้ทันที |
| กำลังโหลด | อ่านจากเครื่อง (ปกติแทบไม่เห็น) | `กำลังโหลด…` | — ไม่มีการรอเน็ต |
| ครั้งแรกหลังเข้ากลุ่ม | กำลังดาวน์โหลดข้อมูลกลุ่มครั้งแรก (architecture §Pull) | `กำลังดึงข้อมูลกลุ่มครั้งแรก…` — รายการที่มาแล้วแสดงเลย | ใช้ได้ แต่อาจยังไม่ครบ |
| ออฟไลน์ / Pending Sync | บันทึกตอนไม่มีเน็ต หรือรอส่ง | ตัวบอกภาพรวม `รอส่ง N` (E01-S10); ต่อแถว `ค้างส่ง` ขึ้นกับ Q20 | ใช้งานต่อได้ทุกอย่าง — **ไม่ใช่ error** |

| error ถาวร | ส่งไม่ผ่าน (เช่น rules ปฏิเสธ) | ภาพรวม: `ส่งข้อมูลไม่สำเร็จ` `[ลองใหม่]` | กดลองใหม่; ข้อมูลในเครื่องไม่หาย |
| Conflict | หลายเครื่องแก้ฟิลด์เดียวกัน / ฟิลด์ strict (D-30) | แถว: `⟨ไอคอน Conflict⟩ ขัดกัน`; ในหน้ารายละเอียด ฟิลด์นั้นแสดง **ค่าก่อนแก้** + ข้อความกลางด้านล่าง | `[เลือกค่า]` ▸ หน้าตัดสินของ E01-S11 |
| ข้อมูลไม่ถูกต้อง | กรอกผิด | ข้อความใต้ฟิลด์ (เฉพาะ story) ไม่ล้างค่าที่กรอก | แก้แล้วบันทึกใหม่ |
| สิทธิ์ | ใช้ตำแหน่ง / กล้อง / คลังรูป | เฉพาะ S02 (ดู §3.3–3.4) | — |
| รอข้อมูล | การแก้มาถึงก่อนต้นฉบับ (architecture §ตรวจ Conflict) | แสดงค่าล่าสุดที่รู้ — ไม่มีข้อความพิเศษ | ใช้ได้ |

## 2. E03-S01 คนและผู้ซื้อ

### 2.1 Flow — เพิ่มคน
1. ตั้งค่า ▸ ข้อมูลฟาร์ม ▸ คน
2. `[+ เพิ่มคน]` → ฟอร์ม
3. ใส่ชื่อ*, เลือกบทบาท (เลือกได้หลายข้อ)
4. `[บันทึก]` → ตรวจ:
   - ชื่อว่าง → `ใส่ชื่อ`
   - ไม่เลือกบทบาท → ขึ้นกับ Q4
   - ชื่อซ้ำกับคนที่มีอยู่ (ไม่รวมที่เก็บถาวร) → **เตือน ไม่ขวาง** (ข้อเสนอ P1): `มี "⟨ชื่อ⟩" อยู่แล้ว — เพิ่มเป็นอีกคนใช่ไหม` `[เพิ่มอีกคน]` `[ไม่เพิ่ม]`
5. บันทึกในเครื่อง → กลับรายการ (สถานะส่งตาม §1.4)

### 2.2 Flow — แก้ชื่อ / บทบาท
1. รายการ ▸ แตะแถว → หน้ารายละเอียดคน
2. `[แก้]` → ฟอร์มเดิมพร้อมค่า → `[บันทึก]`
3. ข้อความหลังเปลี่ยนชื่อ: `เปลี่ยนชื่อแล้ว — บันทึกเก่าแสดงชื่อใหม่` (id เดิม — MD-5)
4. เอาบทบาท "คนกรีด" ออกขณะยังมีการมอบหมายที่มีผล (S05) → เตือน: `⟨ชื่อ⟩ ยังรับผิดชอบ N จุดชั่ง — เอาบทบาทคนกรีดออกแล้ว จุดเหล่านั้นยังมอบหมายอยู่จนกว่าจะเปลี่ยน` `[เอาออก]` `[ยกเลิก]` (ดู Q5)

### 2.3 Flow — เก็บถาวรคน
ตามรูปแบบกลาง §1.3 · ถ้าเป็นคนกรีดที่ยังมีการมอบหมายที่มีผล → ข้อความยืนยันเพิ่มบรรทัด
`ยังรับผิดชอบ: ⟨ชื่อจุด⟩, ⟨ชื่อจุด⟩ — หลังเก็บถาวร จุดเหล่านี้จะขึ้นคำเตือน "ยังไม่มีคนกรีด"` (Q5)

### 2.6 ผู้ซื้อ
Flow เหมือนคน (§1.3) ฟิลด์มีแค่ **ชื่อ*** — PRD §รายการที่ยังเปิด ระบุ "รายละเอียดผู้ซื้อ" ยังไม่มี จึงไม่เพิ่มฟิลด์อื่น
```

⟨ชื่อผู้ซื้อ⟩                                              ▸
[+ เพิ่มผู้ซื้อ]
ที่เก็บถาวร (N) ▸
```
- `ใช้ล่าสุด` = ผู้ซื้อของการขายล่าสุด เป็นค่าเริ่มต้นการขายใหม่ (MD-6) — คำนวณเอง ผู้ใช้ไม่ต้องตั้ง
- ว่าง: `ยังไม่มีผู้ซื้อ — เพิ่มได้ตอนเริ่มการขายครั้งแรก` `[+ เพิ่มผู้ซื้อ]`
- ผู้ซื้อ "ใช้ล่าสุด" ถูกเก็บถาวร → การขายใหม่ไม่มีค่าเริ่มต้น ต้องเลือก (Q6)

### 2.7 สถานะเฉพาะ S01
- เครื่องที่ 2 เห็นคนที่เครื่องแรกสร้างหลัง sync — แถวโผล่ในรายการเอง ไม่ต้อง reload (E01-S10 AC "เปลี่ยนเองเมื่อ online")
- สองเครื่องสร้าง "แดง" ตอนออฟไลน์ → ได้ 2 แถว (create รวมอัตโนมัติ — architecture ตาราง) — ผู้ใช้เห็นทั้งสองและเก็บถาวรแถวหนึ่ง; การรวมสองคนเป็นคนเดียวไม่อยู่ในขอบเขต (ดู §10 P1)
- สองเครื่องแก้ชื่อคนเดียวกันต่างกัน → Conflict (ฟิลด์บรรยายเดียวกัน) ตาม §1.4
- เก็บถาวรเครื่องหนึ่ง + แก้อีกเครื่อง → Conflict (ลบ vs แก้) แสดง `ยังไม่เก็บถาวร — ค่าก่อนแก้` + `[เลือกค่า]`
- กรณีชื่อซ้ำ (P1) เป็นข้อเสนอ — ระหว่างรอเจ้าของ ไม่มีคำเตือน

## 3. E03-S02 สวน (ที่ดิน) และประวัติพื้นที่

### 3.1 Flow — เพิ่มสวน
1. ตั้งค่า ▸ ข้อมูลฟาร์ม ▸ สวนและจุดชั่ง ▸ `[+ เพิ่มสวน]`
2. ใส่ ชื่อ*, ประเภท* (ยาง / ทุเรียน), พื้นที่ + วันที่มีผล (ไม่บังคับ — Q7), ปีที่ปลูก (ไม่บังคับ), GPS (ไม่บังคับ)
3. ทุเรียน → มีฟิลด์ `ไฟล์สัญญาเช่า` เพิ่ม (แนบไฟล์/รูปเท่านั้น — คำตอบเจ้าของ: รอ E11)
4. `[บันทึก]` → หน้ารายละเอียดสวน (เพื่อเพิ่มจุดชั่งต่อได้ทันที)

### 3.2 Flow — เปลี่ยนพื้นที่ (ไม่ทับของเดิม)
1. รายละเอียดสวน ▸ พื้นที่ ▸ `[เปลี่ยนพื้นที่]`
2. ใส่ พื้นที่ใหม่ (ไร่)*, มีผลตั้งแต่* (ค่าเริ่มต้น วันนี้)
3. ตรวจ: ไม่ใช่ตัวเลข / ≤ 0 → `ใส่พื้นที่เป็นตัวเลขมากกว่า 0`; วันที่ซ้ำกับรายการเดิม → Q8
4. บันทึก → เพิ่มบรรทัดใหม่ในประวัติ; บรรทัดเดิมยังอยู่
- แก้บรรทัดที่ใส่ผิด: แตะบรรทัด → `[แก้]` / `[ลบ]` (Soft Delete — E01-S04); พื้นที่เป็นตัวเลข → แก้ซ้อนสองเครื่อง = Conflict

### 3.3 Flow — GPS
1. `[ใช้ตำแหน่งตอนนี้]` → ขอสิทธิ์ตำแหน่ง (ครั้งแรก)
2. แสดง `กำลังหาตำแหน่ง…` `[ยกเลิก]` (GPS ใช้ได้ออฟไลน์ แต่อาจช้า)
3. ได้แล้ว → แสดงพิกัด + `[ลบตำแหน่ง]`
- ไม่ใส่ = ป้าย `ไม่ทราบ` (MD-1, SYNC-12)
- ไม่ได้รับสิทธิ์: `แอปยังไม่ได้รับอนุญาตให้ใช้ตำแหน่ง — เปิดได้ที่ตั้งค่าของโทรศัพท์` (เว็บ: `…ที่ตั้งค่าของเบราว์เซอร์`)
- หาไม่เจอภายในเวลาที่กำหนด: `หาตำแหน่งไม่ได้ — ลองในที่โล่ง แล้วกดใหม่` `[ลองอีกครั้ง]`
  (ตั้งใจใช้ `ลองอีกครั้ง` ไม่ใช้ `ลองใหม่` — คำ `ลองใหม่` สงวนไว้สำหรับ sync ตาม D-3)
- ห้ามบันทึกพิกัดอัตโนมัติโดยผู้ใช้ไม่กด

### 3.4 Flow — ไฟล์สัญญาเช่า (ทุเรียน)
1. `[แนบไฟล์สัญญา]` → เลือก `ถ่ายรูป` / `เลือกรูปหรือไฟล์`
2. ไฟล์เข้าคิวในเครื่องทันที เครื่องที่แนบแสดงสถานะส่งตาม §1.4 (ไฟล์ที่ยังไม่ขึ้นนับเป็น Pending Sync — architecture §สื่อ)
3. ไม่ได้สิทธิ์กล้อง: `แอปยังไม่ได้รับอนุญาตให้ใช้กล้อง — เปิดได้ที่ตั้งค่าของโทรศัพท์`
   ไม่ได้สิทธิ์คลังรูป/ไฟล์: `แอปยังไม่ได้รับอนุญาตให้เปิดรูปในเครื่อง — เปิดได้ที่ตั้งค่าของโทรศัพท์`
4. เครื่องอื่นเห็นรายการไฟล์ก่อนตัวไฟล์ → `ไฟล์รอส่ง — จะเปิดได้เมื่อเครื่องที่แนบมีเน็ต` (คำเดียวกับ architecture §สื่อ)

## 4. E03-S03 จุดชั่ง (= กอง) และโครงสร้างตั้งต้น

### 4.1 Flow — เพิ่มจุดชั่ง
1. รายละเอียดสวน ▸ จุดชั่ง ▸ `[+ เพิ่มจุดชั่ง]`
2. ใส่ ชื่อจุด* อย่างเดียว — **ไม่มีฟิลด์โซนในฟอร์มนี้**: การเข้า/ออกโซนมีวันที่มีผลเสมอ จึงทำจากหน้าโซนเท่านั้น (§5.3–5.6, S04 AC4)
   หน้ารายละเอียดจุดแสดงโซนปัจจุบันแบบอ่านอย่างเดียว + ทางไปหน้าโซน
3. คนกรีด: หลังบันทึก แสดงทางลัด `มอบหมายคนกรีดให้จุดนี้` ▸ S05 (ไม่บังคับในฟอร์มนี้)
4. ตรวจ: ชื่อว่าง → `ใส่ชื่อจุดชั่ง`; ชื่อซ้ำในสวนเดียวกัน → Q10

### 4.2 Flow — แก้ / เก็บถาวรจุดชั่ง
- แก้ชื่อ: id เดิม การขายเก่าแสดงชื่อใหม่ (MD-3)
- เก็บถาวร: ตามรูปแบบกลาง; เพิ่มบรรทัด `การขายเก่ายังอ้างถึงจุดนี้ได้` · ถ้ามีการขาย Draft ที่ใช้จุดนี้อยู่ → ผลตาม Q22

### 4.3 Flow — สร้างโครงสร้างตั้งต้น (MD-3)
จุดเริ่ม: ปุ่มในหน้าว่างของรายการสวน (§3.5) — **แสดงเฉพาะเมื่อกลุ่มยังไม่มีจุดชั่งเลย และดึงข้อมูลกลุ่มครั้งแรกเสร็จแล้ว**
(เครื่องที่เพิ่งเข้ากลุ่มเห็นรายการว่างระหว่างดาวน์โหลด — ซ่อนปุ่มไว้กันสร้างซ้ำ; ข้อเสนอ P2)
1. แตะ `[สร้างโครงสร้างตั้งต้น]` → หน้าใส่ชื่อ
2. ผู้ใช้ใส่ชื่อจุดทั้ง 5 ช่อง (บังคับทุกช่อง — ไม่มีชื่อแต่งให้, ช่องว่างไม่มีค่าเติม มีแต่คำแนะนำ `ใส่ชื่อจุด`)
3. คนกรีด แดง / นัด: แอปเลือกคนชื่อนั้นที่มีบทบาทคนกรีดให้; ถ้ายังไม่มีหรือมีหลายคนชื่อเดียวกัน → ช่องนั้นให้เลือกจาก
   `PeoplePicker` (เพิ่มคนใหม่ในขั้นเดียวได้ §2.5) — ต้องครบก่อนสร้าง เพราะ S05 AC5 ผูกจุดของแดง → แดง, จุดของนัด → นัด
4. `[สร้าง]` → ตรวจ: ช่องว่าง → `ใส่ชื่อให้ครบทุกจุด` (ชี้ช่องที่ว่าง); ยังไม่เลือกคนกรีด → `เลือกคนกรีดให้ครบ`
5. สร้างในเครื่องทันที: สวน 2 แห่ง (ถ้ายังไม่มีชื่อนี้) + จุด 5 จุด + การมอบหมายตั้งต้นตาม S05 AC5 (วันเริ่มตาม Q11)

```

  คนกรีด: แดง ⟨เลือก ▸ ถ้ายังไม่มี⟩ · นัด ⟨เลือก ▸ ถ้ายังไม่มี⟩
```

**สร้างซ้ำจากสองเครื่องตอนออฟไลน์** (story §Offline): หลัง sync จะมีจุดเกิน — ระบบไม่รวมเอง
- รายการจุดชั่งแสดงทุกจุดตามจริง
- ถ้าสวนเดียวกันมีจุดชื่อเหมือนกัน → (ข้อเสนอ P2) แถวทั้งสองมีหมายเหตุ `ชื่อซ้ำ` และหัวรายการแสดง
  `มีจุดชั่งชื่อซ้ำ — ถ้าสร้างซ้ำจากอีกเครื่อง เก็บถาวรจุดที่ไม่ใช้ได้` (ไม่ขวาง)

```
⟨ชื่อโซน⟩   ตั้งแต่ ⟨วันที่⟩ · จุด: ⟨ชื่อจุด⟩, ⟨ชื่อจุด⟩     ▸
[+ เพิ่มโซน]   [แยกโซน]   [รวมโซน]
เลิกใช้แล้ว ▸   ⟨ชื่อโซน⟩ ⟨วันที่⟩ – ⟨วันที่⟩
```
- `[แยกโซน]` แสดงเมื่อมีโซนที่มี ≥ 2 จุด · `[รวมโซน]` แสดงเมื่อมี ≥ 2 โซน
- รายละเอียดโซน: ชื่อ, ตั้งแต่, จุดในโซน, คนกรีด (ถ้ามอบหมายระดับโซน — S05), `[แก้ชื่อ]`, `[เลิกใช้โซน]` (แยกห่าง)

### 5.3 Flow — เพิ่มโซน
1. `[+ เพิ่มโซน]` → ชื่อโซน*, มีผลตั้งแต่* (ค่าเริ่มต้น วันนี้ — เลือกย้อนหลังได้), เลือกจุดชั่ง `[ ]` (จากจุดของสวนนี้ที่ยังไม่มีโซน ณ วันนั้น)
2. เลือกวันที่ย้อนหลัง → คำอธิบาย `บันทึกตั้งแต่ ⟨วันที่⟩ จะนับว่าอยู่โซนนี้` (MD-2 AC5)
3. ตรวจ: ชื่อว่าง → `ใส่ชื่อโซน`; วันที่ในอนาคต → Q12; จุดที่มีโซนอยู่แล้ว ณ วันนั้น → ไม่ขึ้นให้เลือก (ย้ายจุดระหว่างโซนใช้ แยก/รวม — Q13)
4. บันทึก → รายการโซน

### 5.4 Flow — แยกโซน (รูปแบบตาม Q13)
1. `[แยกโซน]` → เลือกโซนต้นทาง
2. ตั้งชื่อโซนใหม่ (อย่างน้อย 1)
3. ต่อจุด: เลือกว่าอยู่ `⟨โซนเดิม⟩` หรือ `⟨โซนใหม่⟩` — ทุกจุดต้องมีที่ไป
4. มีผลตั้งแต่* (ค่าเริ่มต้น วันนี้)
5. หน้าสรุปก่อนยืนยัน:
```
แยก "⟨โซนเดิม⟩" ตั้งแต่ ⟨วันที่⟩
⟨โซนเดิม⟩: ⟨ชื่อจุด⟩
⟨โซนใหม่⟩: ⟨ชื่อจุด⟩, ⟨ชื่อจุด⟩
บันทึกก่อนวันที่นี้ยังเป็นโครงสร้างเดิม
[ยืนยันแยกโซน]            [กลับไปแก้]
```
6. ตรวจ: วันที่ก่อนวันเริ่มของโซนเดิม → `วันที่ต้องไม่ก่อนวันเริ่มของโซน (⟨วันที่⟩)`; โซนใหม่ไม่มีจุดเลย → `โซนใหม่ต้องมีอย่างน้อย 1 จุด`

### 5.5 Flow — รวมโซน
1. `[รวมโซน]` → เลือกโซน ≥ 2 `[ ]`
2. ผลลัพธ์: `( ) ใช้ชื่อ ⟨โซนที่เลือก⟩` … `( ) ตั้งชื่อใหม่ ____`
3. มีผลตั้งแต่* → สรุป `รวม ⟨A⟩, ⟨B⟩ เป็น ⟨ชื่อ⟩ ตั้งแต่ ⟨วันที่⟩ — บันทึกก่อนวันที่นี้ยังเป็นโครงสร้างเดิม` `[ยืนยันรวมโซน]` `[กลับไปแก้]`
4. การมอบหมายคนกรีดกับการรวม/แยกโซน (โซนมอบหมายต่างคน, ระดับโซนปนระดับจุด, โซนที่แยกออกได้คนกรีดเดิมไหม) → Q14
   ข้อความถ้าเจ้าของเลือก ★: `รวมไม่ได้ — ⟨A⟩ กับ ⟨B⟩ มอบหมายคนกรีดต่างกัน หรือมอบหมายคนละระดับ แก้การมอบหมายก่อน`

### 5.6 Flow — เลิกใช้โซน
ยืนยัน: `เลิกใช้ "⟨โซน⟩" ตั้งแต่ ⟨วันที่⟩ ไหม — จุด ⟨ชื่อจุด⟩ จะไม่มีโซนตั้งแต่วันนั้น บันทึกเก่ายังเห็นโซนนี้` `[เลิกใช้โซน]` `[ยกเลิก]`

### 5.7 สถานะเฉพาะ S04
- แยก/รวมโซนเดียวกันจากหลายเครื่อง: story S04 ให้เป็น Conflict แต่ทั้งสองฝั่งเป็น event สร้างใหม่ที่ architecture รวมอัตโนมัติ —
  ยังไม่มีกติกา (§10 P6) ข้อเสนอการแสดงระหว่างรอ: **โครงสร้างก่อนการเปลี่ยนทั้งสอง** + หัวรายการ
  `⟨ไอคอน Conflict⟩ ขัดกัน — โครงสร้างโซนถูกเปลี่ยนจากหลายเครื่อง แสดงโครงสร้างเดิมจนกว่าจะเลือก` `[เลือกค่า]` ▸ E01-S11
  หน้าตัดสินแสดงสองแบบเป็นสรุปแบบเดียวกับ §5.4 ข้อ 5 ไม่แสดง event ดิบ
- ไม่มีหน้า "ประวัติโซน" แยก — วันที่ตั้งแต่/ถึงในรายการ "เลิกใช้แล้ว" พอสำหรับ MVP (SYNC-9: ไม่มี UI ประวัติเวอร์ชันใน V1)

## 6. E03-S05 มอบหมายคนกรีด ↔ จุดชั่ง/โซน

### 6.1 จุดเข้า
- รายละเอียดจุดชั่ง (หรือโซน) ▸ แถว `คนกรีด`
- รายละเอียดคน (คนกรีด) ▸ `จุดที่รับผิดชอบตอนนี้` (อ่าน + ทางลัดไปจุด)

### 6.2 หน้าจอ — คนกรีดของจุด
```
‹ ⟨ชื่อจุด⟩                คนกรีด
ตอนนี้: แดง  ตั้งแต่ ⟨วันที่⟩                         [เปลี่ยนคนกรีด]
ประวัติ
  นัด   ⟨วันที่⟩ – ⟨วันที่⟩
[+ มอบหมาย]                 ← แสดงเมื่อตอนนี้ยังไม่มีคนกรีด
```
- ไม่มีคนกรีด: `ยังไม่มีคนกรีด — การชั่งที่จุดนี้ทำได้ แต่จะมีคำเตือน` `[+ มอบหมาย]`
- จุดอยู่ในโซนที่มอบหมายระดับโซน: `คนกรีดมาจากโซน "⟨โซน⟩": แดง` + ทางไปโซน — ไม่มีปุ่มมอบหมายที่จุด (คำตอบเจ้าของ: มอบหมายได้ระดับเดียว)

### 6.3 Flow — มอบหมาย
1. `[+ มอบหมาย]` → ฟอร์ม:
```
‹ ยกเลิก                  มอบหมายคนกรีด
คนกรีด*       [เลือก ▸]       (PeoplePicker กรอง "คนกรีด")
ที่*          ⟨ชื่อจุด⟩ / ( ) จุดชั่ง ( ) โซน — ถ้าสวนมีโซน
ตั้งแต่*       ⟨วันนี้⟩
ถึง           ยังมีผล  [ตั้งวันสิ้นสุด]
[บันทึก]
```
2. ตรวจ:
   - ช่วงทับการมอบหมายเดิมบนที่เดียวกัน → `ช่วงวันที่ทับกับ ⟨ชื่อ⟩ (⟨วันที่⟩ – ⟨วันที่/ยังมีผล⟩) — ปรับวันที่ หรือใช้ "เปลี่ยนคนกรีด"` (SALE-4)
   - มอบหมายจุดที่อยู่ในโซนที่มอบหมายแล้ว (หรือกลับกัน) ในช่วงที่ทับกัน → `"⟨โซน⟩" มอบหมายให้ ⟨ชื่อ⟩ อยู่แล้ว — มอบหมายได้ระดับเดียว: แก้ที่โซน หรือสิ้นสุดการมอบหมายโซนก่อน`
   - `ถึง` ก่อน `ตั้งแต่` → `วันสิ้นสุดต้องไม่ก่อนวันเริ่ม`

### 6.4 Flow — เปลี่ยนคนกรีด (ข้อเสนอ: ทางลัดที่ไม่ทำให้ช่วงทับ)
1. `[เปลี่ยนคนกรีด]` → คนกรีดใหม่*, ตั้งแต่* (ค่าเริ่มต้น วันนี้)
2. สรุป: `แดง รับผิดชอบถึง ⟨วันก่อนหน้า⟩ · นัด เริ่ม ⟨วันที่⟩ — การขายก่อนวันที่นี้ไม่เปลี่ยน` `[ยืนยัน]` `[กลับไปแก้]`
3. บันทึก = ปิดช่วงเดิม + เปิดช่วงใหม่ (MD-4 AC3) — ความหมาย "ถึง" รวมวันนั้นหรือไม่ ดู Q15
- วันที่ใหม่ ≤ วันเริ่มของคนเดิม → `วันที่ต้องหลังวันเริ่มของ ⟨ชื่อ⟩ (⟨วันที่⟩)`

### 6.5 คำเตือนตอนเลือกจุด (ใช้ใน E04 — AC4)
เลือกจุดที่ไม่มีคนกรีด ณ วันขาย → **เตือน ไม่ขวาง**:
`จุดนี้ยังไม่มีคนกรีด ณ วันที่ขาย — ชั่งต่อได้ มอบหมายทีหลังได้` `[ชั่งต่อ]` `[มอบหมายตอนนี้]`
(ความหมายของเข่งที่ชั่งก่อนมอบหมาย → Q16; รายละเอียดหน้าชั่งอยู่ MF-21)

### 6.6 สถานะเฉพาะ S05
- หลายเครื่องมอบหมายทับช่วงกันตอนออฟไลน์: story S05 ให้เป็น Conflict แต่เป็น create สองรายการ ไม่มี "ค่าก่อนแก้" —
  ยังไม่มีกติกาใน architecture (§10 P6) ข้อเสนอการแสดงระหว่างรอ: ใช้การมอบหมายเดิมก่อนทั้งสองรายการ
  (ถ้าไม่มี = `ยังไม่มีคนกรีด`) + `⟨ไอคอน Conflict⟩ ขัดกัน — มอบหมายทับช่วงจากหลายเครื่อง` `[เลือกค่า]`
- การขายที่ได้รับผลจะปิด/สรุปเงินได้หรือไม่ระหว่างรอ → Q23 (`blockingConflicts` ตอนนี้ดูเฉพาะ Conflict ในการขาย)

## 7. E03-S06 ส่วนแบ่งรายคนกรีด

### 7.1 หน้าจอ — ส่วนแบ่งของคนกรีด (จากรายละเอียดคน)
```
‹ ⟨ชื่อ⟩                   ส่วนแบ่ง
ตอนนี้: เจ้าของ 50 · คนกรีด 50 (ค่าเริ่มต้น)            [เปลี่ยนส่วนแบ่ง]
```

### 7.2 Flow — เปลี่ยนส่วนแบ่ง
1. `[เปลี่ยนส่วนแบ่ง]` →
```

(•) เจ้าของ 50 · คนกรีด 50
( ) เจ้าของ 60 · คนกรีด 40
( ) เจ้าของ 70 · คนกรีด 30
( ) กำหนดเอง   ⟨ฝั่งที่ใส่ — Q17⟩ ____ %   → อีกฝั่ง ⟨100 − ค่า⟩ %
มีผลตั้งแต่*    ⟨วันนี้⟩
การขายก่อนวันที่นี้ไม่เปลี่ยน
[บันทึก]
```
2. กำหนดเอง: แสดงอีกฝั่งทันทีที่พิมพ์ (ไม่ต้องกดคำนวณ)
3. ตรวจ (AC3 — ไม่บันทึก):

   - นอก 0–100 → `ใส่ได้ตั้งแต่ 0 ถึง 100`
   - ว่าง → `ใส่ตัวเลขส่วนแบ่ง`
4. วันที่มีผลย้อนไปก่อนการขายที่ Completed ของคนกรีดนี้ → Q18
5. บันทึก → `บันทึกส่วนแบ่งแล้ว — ใช้กับการขายตั้งแต่ ⟨วันที่⟩`

- ค่าเริ่มต้น: กดค้าง 0.7 วินาที, จับนับซ้ำ 8 วินาที (คำตอบเจ้าของ); เสียง **เปิด** (SALE-16 "อ่านเลขเข่งทุกเข่ง … ปิดได้")
- ปุ่ม `[−]` `[+]` ปรับทีละ 0.1 วินาที / 1 วินาที; ถึงขอบ ปุ่มฝั่งนั้นกดไม่ได้ (ค่านอกช่วงเลือกไม่ได้ตั้งแต่ต้น จึงไม่มีข้อความผิด)
- `[ลองกดค้างที่นี่]` เป็นข้อเสนอ (§10 P5) — ไม่อยู่ใน AC

### 8.4 สถานะเฉพาะ S07
- ค่ากลุ่มฟิลด์เดียวกันแก้ซ้อนหลายเครื่อง → Conflict (architecture ตาราง) แสดงค่าก่อนแก้ + ข้อความ Conflict กลาง (§1.4) ที่หัวข้อนั้น
- หมายเหตุ: `architecture.md` ตาราง Conflict ยังเขียน "ระยะกดค้าง" เป็นค่ากลุ่ม — ล้าสมัยหลังคำตอบเจ้าของ (เป็นของเครื่อง) ส่งต่อ solution-architect
- ค่าเครื่อง: ไม่มี Pending/Conflict (ไม่ sync)

## 9. E03-S08 ขนาดตัวอักษร

### 9.1 หน้าจอ (ในหน้า "เครื่องนี้")
```
ขนาดตัวอักษร
  ( ) เล็ก   (•) กลาง (ค่าเริ่มต้น)   ( ) ใหญ่
  ตัวอย่าง: เข่ง 12 · แดง · 50 กก.
  ตัวเลขนับบนจอสาธารณะไม่เปลี่ยนตามขนาดนี้
```
### 9.2 Flow
1. แตะตัวเลือก → **ใช้ทันทีทั้งแอป** ไม่มีปุ่มบันทึก (ผู้ใช้เห็นผลก่อนออกจากหน้า)
2. ค่าคงอยู่หลังปิด/เปิดแอป; ใช้ได้ออฟไลน์; ไม่ sync (เครื่องอื่นไม่เปลี่ยน)
- ชื่อตัวเลือกใช้ `เล็ก / กลาง / ใหญ่` แทน S/M/L เพราะ UI ภาษาไทยเท่านั้น (D-20) — ค่าใน token ยังเป็น S/M/L
- สถานะ: N/A ทั้ง Pending/Conflict/error (ไม่ sync) — ว่าง/โหลด N/A
